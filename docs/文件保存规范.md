# 文件保存规范

本规范定义项目各目录的职责边界、文件归置规则和命名约定，作为新增文件时的判断依据。

## 目录结构总览

```
llm_benchmark/
├── data_pipeline/         MIMIC 数据处理管道
│   ├── mimic_raw_archive/     原始 MIMIC 表 → 单次住院 raw JSONL
│   ├── parquet_to_jsonl/      已废止的派生 visit archive 实验实现
│   ├── mimic_dictionary/      官方编码字典构建
│   ├── clean_clinical_archive/ 字典解码与 POE 临床可读清洗
│   └── mimic_episode/         Episode 聚合管线（41 表 → parquet）
├── rwd_pipeline/          旧版抽取 / 清洗 / 标准化管线（17 列 CSV 路线）
├── mcq_generation/        MCQ 出题模块（当前仅设计文档，代码待实现）
├── eda/                   探索性数据分析
│   ├── exploratory/           先前版本 EDA 探索
│   └── analysis/              当前及后续 EDA 分析
├── docs/                  项目文档
│   ├── design/                方法学与设计文档
│   ├── reports/               分析报告与数据清单
│   └── reference/             参考资料（MIMIC 字段文档、表 schema 速查）
├── tests/                 测试套件（扁平结构）
├── data/                  本地数据与工具（.gitignore 排除，不推送）
└── 根目录                 项目级配置与入门文档
```

## 各目录职责

### 数据层代码模块

MIMIC 数据层代码统一收纳在 `data_pipeline/`，使用 `data_pipeline.<module>` 包路径；评测层和旧路线保留各自目录。

| 模块 | 职责 | 新增代码归属 |
|---|---|---|
| `data_pipeline/mimic_raw_archive/` | 当前数据底座：按原始主键构建单次住院 JSONL | 原始归档、分片、续跑和验证代码 |
| `data_pipeline/parquet_to_jsonl/` | 已废止的派生 visit archive 实验路线 | 仅限历史复现和审计，不新增主线功能 |
| `data_pipeline/mimic_dictionary/` | 官方字典构建 | 字典生成与字典查询兼容入口 |
| `data_pipeline/clean_clinical_archive/` | 临床可读归档 | 字典解码、POE解析、规则文档与本地字典 |
| `rwd_pipeline/` | 旧版 17 列 CSV 路线的抽取/清洗/标准化 | 该路线的维护与迭代 |
| `data_pipeline/mimic_episode/` | Episode 聚合：跨表聚合为 episode-level parquet | 聚合管线相关代码 |

### `data_pipeline/mimic_episode/scripts/` 按功能拆分

- `pipeline/` — 对数据层执行写操作的脚本（运行管线、中断恢复、导出、清洗、质量报告）
- `profiling/` — 只读分析脚本（不改数据），轻量文本报告（md/json/txt）输出到此目录下

重数据（parquet 等）始终写到外部 G 盘目录，不进 git。

### spec 文档跟模块走

模块级实现规范（如 `rwd_benchmark_extraction_spec.md`）放在对应模块目录下，不收编到 `docs/`。这样改代码时能直接对照 spec。

### `docs/` 按类别拆分

| 子目录 | 内容 | 判定规则 |
|---|---|---|
| `docs/design/` | 方法学、构建方案、字段映射 | 描述"怎么做"的设计决策 |
| `docs/reports/` | 分析报告、仪表盘、数据清单 | 描述"结果是什么"的分析产出 |
| `docs/reference/` | MIMIC 字段文档、表 schema 速查 | 供查阅的参考资料，非本项目产出 |

项目概览类文档（接手文档、流程梳理、流程图）直接放 `docs/` 根。

### `eda/` 按阶段命名

- `exploratory/` — 先前版本的 EDA 探索，保留为项目理解的一部分
- `analysis/` — 当前及后续持续使用的 EDA 分析目录

不使用 v1/v2 等版本号命名目录；版本演进由 git 历史管理。

### `data/`（不推送）

`data/` 整体被 `.gitignore` 排除。本地存放：
- MIMIC 原始数据与派生数据
- 本地工具脚本（如 `audit_mimic_download.ps1`）
- 设计草稿文档

这些文件不推送到 GitHub。

## 命名约定

- 目录命名用英文小写 + 连字符（`parquet_to_jsonl`、`run_mimic_pipeline`）
- 文档文件可使用中文名（与项目已有文档一致）
- 代码文件用英文小写 + 下划线（Python 惯例）
- SQL 文件用动词开头（`build_*`、`create_*`、`export_*`）
- 临时调试脚本用下划线前缀（`_*.py`），使命完成后删除，不长期保留

## .gitignore 要点

| 排除项 | 原因 |
|---|---|
| `data/` | 患者级数据、本地工具，不对外分发 |
| `*.csv` / `*.parquet` | 派生数据文件 |
| `*.pdf` | 本地论文 |
| `.env` / `.env.*` | 凭据（仅记位置不记值） |
| `.venv/` | 虚拟环境 |
| `handoffs/` | 交接文档，按惯例不版本控制 |

## 新增文件决策流程

1. 是数据层代码？→ 放 `data_pipeline/` 下对应功能模块（当前主线为 `mimic_raw_archive/` 与 `clean_clinical_archive/`）
2. 是模块级 spec？→ 放模块目录下
3. 是文档？→ 按 design / reports / reference 归类到 `docs/`
4. 是测试？→ 放 `tests/`，文件名前缀标明归属模块
5. 是数据或本地工具？→ 放 `data/`（不推送）
6. 是临时调试脚本？→ 用 `_` 前缀，完成后删除
