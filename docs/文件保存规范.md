# 文件保存规范

本规范定义项目各目录的职责边界、文件归置规则和命名约定，作为新增、移动或归档文件时的判断依据。适用范围是**整个仓库**，不限于 `docs/`。

> 配套阅读：根目录 [`README.md`](../README.md)（当前进展与整体计划）、[`docs/README.md`](README.md)（docs 索引）。

## 项目分层

项目从下到上分三层，数据层产物逐层喂给评测层：

1. **数据层** `data_pipeline/`：MIMIC 原始表 → 单次住院原始归档 → 字典解码与 POE 解析 → 事件清洗 → 确定性标准化 → 无损事件聚合 → 文本 NER 输入。
2. **评测层** `evaluation_pipeline/` + `tasks/` + `benchmark_common/`：患者级划分、encounter boundary、决策快照、五类 MCQ 出题与 LLM 评测。
3. **外部验证层**：香港 RWD 本地适配与外部验证（规划中，未实现）。

## 目录结构总览

## 数据层 `data_pipeline/`

| 模块 | 职责 | 新增代码归属 |
|---|---|---|
| `mimic_raw_archive/` | 主线第 1 步：按原始主键构建单次住院 `mimic_admission_raw` JSONL | 原始归档、分片、续跑、manifest 与验证代码 |
| `clean_clinical_archive/` | 主线第 2 步：字典解码 + POE 解析，产出临床可读 JSONL | 字典解码、POE 时间线解析 |
| `event_pipeline/` | 主线第 3、4 步：事件清洗、确定性标准化、质量标记与审计 | 清洗/归一化规则、合同、质量与审计代码 |
| `event_aggregation/` | 无损事件聚合：把标准化事件连回完整原文与源行血缘 | 聚合与追溯代码 |
| `text_ner/` | 文本 NER v1：输入准备、标注界面、全量抽取接口 | v1 相关代码 |
| `text_ner_v2/` | 文本 NER v2：干净重做版（确定性 span 回填、确定性分块） | v2 相关代码 |
| `phenotype/` | 表型特征：条件空间、药物类别、人口学、生命体征标志 | 表型/特征提取代码 |
| `tools/mimic_dictionary/` | 官方编码字典构建工具 | 字典生成与查询入口 |
| `archived/` | 已归档路线：`mimic_episode`（Episode 聚合）、`parquet_to_jsonl`（派生 visit archive） | 仅历史复现与审计，不新增主线功能 |
| `mimic_source_catalog.py` | 活动共享契约：MIMIC 源表定义，供原始归档与归档 Episode 复用 | 源表清单更新 |

活动主流程不再依赖 `archived/` 内任何文件；两条路线不能混为同一条顺序流程。

## 文档 `docs/`

| 子目录 | 内容 | 判定规则 |
|---|---|---|
| `design/` | 方法学、构建方案、字段映射、标注协议 | 描述“怎么做”的设计决策 |
| `reports/` | 分析报告、仪表盘、数据清单、验收/评测结果 | 描述“结果是什么”的产出 |
| `reference/` | MIMIC 官方字段文档、表 schema 速查 | 供查阅的参考资料 |
| `guides/` | 运行手册、操作 runbook | “如何运行”的步骤说明 |
| `methods/` | 方法/任务协议 | “如何锁定/验证”的规范 |
| `normalization-review/` | 跨批归一化人工审阅操作指南 | 人工审阅操作说明 |
| `text-ner-review/` | Text NER 人工校准操作说明 | 人工校准操作说明 |
| `_archive/` | 已废止、过时或重复的文件 | 不再参与当前工作流，仅保留历史 |

项目概览（当前进展、整体计划、流程）统一由根目录 `README.md` 承载，`docs/` 不再维护重复的概览文档。

## 命名约定

- 目录命名用英文小写 + 连字符（`event_pipeline`、`investigation_selection`）。
- 文档文件可使用中文名（与项目已有文档一致）。
- 代码文件用英文小写 + 下划线（Python 惯例）。
- SQL 文件用动词开头（`build_*`、`create_*`、`export_*`）。
- 临时调试脚本用下划线前缀（`_*.py`），使命完成后删除，不长期保留。
- 报告同一产物的多格式文件（`.md` / `.json` / `.html`）用相同 basename 共置，避免派生重复副本。

## .gitignore 要点

| 排除项 | 原因 |
|---|---|
| `data/` | 患者级数据、本地工具，不对外分发 |
| `tasks/*/output/` | 题目/黄金/划分/评测结果均为可再生派生，不提交 |
| `*.csv` / `*.parquet` | 派生数据文件 |
| `*.pdf` | 本地论文 |
| `.env` / `.env.*`（保留 `.env.example`） | 凭据 |
| `.venv/` / `venv/` | 虚拟环境 |
| `handoffs/` | 交接文档，按惯例不版本控制 |
| `data_pipeline/clean_clinical_archive/dictionaries/` | 本地授权的 MIMIC 字典 |
| `__pycache__/` / `*.py[cod]` | Python 字节码 |

## 新增文件决策流程

1. 是数据层代码？→ 放 `data_pipeline/` 下对应功能模块（当前主线为 `mimic_raw_archive/` → `clean_clinical_archive/` → `event_pipeline/` → `event_aggregation/`，文本支路为 `text_ner_v2/`）。
2. 是评测层代码？→ 五类任务放 `tasks/<task>/`，共享基础放 `benchmark_common/`，正式工程链放 `evaluation_pipeline/`。
3. 是模块级 spec？→ 放对应模块目录下（如 `rwd_pipeline/rwd_benchmark_*_spec.md`），不收编到 `docs/`。
4. 是文档？→ 按 design / reports / reference / guides / methods 归类到 `docs/`。
5. 是配置或 Schema？→ 放 `config/` 或 `schemas/`。
6. 是测试？→ 放 `tests/`，文件名以 `test_<模块>.py` 标明归属。
7. 是数据或本地工具？→ 放 `data/`（不推送）。
8. 是临时调试脚本？→ 用 `_` 前缀，完成后删除。
