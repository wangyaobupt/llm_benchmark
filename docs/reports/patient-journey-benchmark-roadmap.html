数据层全链路

每一阶段均显示输入、处理、输出和门禁。

清洗层时间合同

原始时间
  • event_time：事件发生/开始
  • source_available_time：源系统原始存储/记录
  • recorded_time：录入或核验
泄漏安全时间
  • available_time 不早于 event time
  • 区间事件不早于 completion/end time
  • 源端倒置保留原值、原因和质量标志
  • 仍有有效倒置则原子失败
03

Patient journey 事件流

临床过程包含循环、并行和条件分支，不是刚性直线。

到院/分诊

主诉、生命体征、既往可用信息

初始评估

问题表征、危急程度

检查选择

医嘱与comparison class

结果逐步可用

不是采集即刻可见

诊断形成/修正

允许随新证据迭代

治疗与再评估

订单、处方、执行分层

去向或离院

服务、位置、结局分开

数据模型：Journey → Event → State → Decision node → Evidence edge。每个 node 都能反向追溯到 normalized event、cleaned event 和 raw source row。

Journey 必要字段

  • journey_id、subject_id、encounter refs
  • start/end、split、边界原因
  • 负责服务与物理位置分开
  • active problems、ongoing treatment、unknowns

Journey 验收

  • 事件属于唯一 journey 或 unresolved
  • 同时间并列事件不强排因果
  • 不改写 event/available time
  • 空数组不等于无临床情况
04

决策节点与时间安全快照

冻结“当时已知信息”，而不是把整份病历交给模型。

识别目标动作

明确事件本体和 target window

冻结 index_time

动作发生前

双时间过滤

event ≤ index 且 available ≤ index

阶段过滤

排除 post_hoc / administrative_end

字段白名单

只保留任务所需证据

泄漏审计

时间、语义、身份/划分

冻结 manifest

证据、不可见原因、哈希

时间泄漏

采集时间不等于医生可见时间；结果签署、存储和完成时间共同约束。

语义泄漏

过滤“最终诊断”“已计划PCI”“转入某科后”等直接或隐含答案线索。

身份/划分泄漏

患者互斥、模板和近重复分组；规则、阈值、提示调试只使用development患者。

06

Gold 三轨分离

同一病例可产生不同构念的任务，但不可混题、混名或混分。

A 个体 next-event

单个 encounter 在 target window 内真实发生的有效动作。

措辞：最可能被记录、开立或实施。

B 群体 pattern/rule

development RWD 中冻结候选集合上的稳定 argmax，并在 validation 验证。

措辞：历史 RWD 中最常选择。

C 规范 clinical-best

指南、当地路径与两名专家独立裁定，必要时第三人仲裁。

措辞：当前最佳或优先决策。

每个 gold 的最小证据

construct_type 与唯一任务ID
snapshot 或 rule manifest
冻结候选集合与唯一答案
事件refs或指南版本/页码
支持度与不确定性
专家独立答案和分歧原因
candidate/validated/failed/inconclusive状态
release版本和哈希

泄漏、唯一性、位置偏差

双专家审核

版本化与可追溯

Pilot：每个维度先形成150–200个证据候选和约100道候选题，报告完整漏斗。发现任何未解释未来泄漏、无唯一答案比例>10%、专家一致性不足或无效干扰项过多时停止扩容并修复根因。
08

LLM 与临床参照评测

既看单节点正确率，也看整条旅程是否自洽。

单题与节点

  • accuracy、拒答、解析失败
  • 校准与置信度
  • 严重临床错误等级
  • 患者聚类bootstrap 95% CI

Journey一致性

  • 诊断—治疗
  • 严重程度—去向
  • 治疗反应—离院计划
  • 无证据反转与错误传播

稳健性与参照

  • 题干改写和非决定信息移除
  • 24种答案排列抽样
  • 专科/普通/低年资医生
  • 疾病、场景、年龄、性别亚组
09

香港 RWD 适配与外部验证

不是替换数据源，而是重新完成治理、映射、时间语义和 gold 本地化。

必须本地重建

  • 字段crosswalk与数据资产合同
  • 编码、药物、检验单位和科室本体
  • 下单/采集/验证/发布/医生可见时间
  • 患者队列和split
  • 行为gold频率与阈值
  • 香港指南、路径和专家规范gold

外部验证输出

  • 患者结构、疾病谱和缺失模式差异
  • 五节点覆盖率和可构建率
  • 模型两地节点级和journey级性能
  • 行为/规范gold一致与分歧
  • domain shift归因
  • 可迁移与不可迁移结论
10

里程碑与当前执行队列

每一项都有机械验收和停止条件。

里程碑状态交付物通过条件停止条件

现在 → 紧接着 → 最小闭环

  1. 数据支路：枚举ED chief complaint和放射报告 → 稳定文档/章节/span定位 → 输入manifest → 纳排原因与哈希验收；不调用模型。
  2. 评测主线：冻结检查题pattern/rule-concordance的X生成器、候选目录、FDR family、稳定性门禁和manifest。
  3. 汇合闭环：normalized events + 文本证据 → journey → 一个检查节点 → 时间安全payload → 单一构念gold → MCQ → 自动/临床审核 → 小规模试答。
  4. 扩展原则：首个闭环通过后再逐项扩展诊断、治疗、离院和去向，不同时铺开五条未验证实现线。
