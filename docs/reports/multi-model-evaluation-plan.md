# 多模型评测方案 + 人工审核负荷与优化点清单

> 日期：2026-08（当前仓库状态）
> 定位：本文件回答三件事——(1) 如何在五维 bench 上对多个主流大模型展开评测；(2) 当前有哪些必须人工审核、负荷多大；(3) 有哪些可优化点。
> 前置事实：所有任务产物均标记 `exploratory_unreviewed`，gold/阈值/词表为占位值，尚未冻结；正式 LLM 评测「尚未开始」。因此本方案区分「预研探针（现在可做）」与「正式榜单（冻结后）」。

## 1. 多模型评测方案

### 1.1 定位与两条轨道

- **轨道 A：预研探针（现在可做，本方案主体）**
  直接用现有 `validated_rank1.jsonl`（约 221 题）在多模型上跑一遍，回答「这套 bench 大致能拉开多少差距、哪几维最灵敏、哪些题是天花板题/地板题」。结果一律标注 `unreviewed_model_output`，只作内部预研，不进正式报告、不进论文。
- **轨道 B：正式榜单（冻结后）**
  在 gold/协议冻结、`final_test` 一次性盲测、临床审核完成后，用发布集跑多模型，配 Wilson CI / bootstrap + 配对检验，作为可引用结果。**本方案不试图现在启动轨道 B。**

### 1.2 模型选型（分档，以可用 API 为准）

| 档 | 候选（示例） | 选型理由 |
|---|---|---|
| 闭源旗舰 | GPT-4.1 / GPT-4o、o3 / o4-mini（reasoning）、Claude Sonnet 4.5 / Opus 4.1、Gemini 2.5 Pro | 覆盖主流闭源上限 |
| 开源/国产 | DeepSeek V4 系列（含 R1 推理）、Qwen3-Max、Kimi、GLM、Grok、Llama/Mistral（如需本地） | 覆盖「本机已接入」的 DeepSeek/Qwen/Bailian 生态 |
| 小/快模型对照 | 各家的 flash/mini 档 | 测「性价比/小模型下限」，也能暴露 bench 的难度分层 |

选型原则：**每个维度至少 3–5 个异构模型**（不同厂商、不同规模、含 1 个 reasoning 模型），才能看出「维度间相对难度」而非「单一模型误差」。

### 1.3 统一评测 harness（关键工程项）

现状 `evaluate.py` 只支持单 endpoint、单 model、单 provider。多模型需要一次收敛：

1. **一个多 provider 评测器**（替换/包装现有 evaluate.py）：
   - 读一份 `models.yaml/json`（模型名、base_url、api_key 引用、provider、thinking on/off）；
   - 输入统一为 `validated_rank1.jsonl`（五维/六子任务各自一份）；
   - 每模型每维度输出 `eval_results.jsonl` + `eval_results.json`（沿用现有 schema，补 `model`、`provider`、`prompt_hash`、`timestamp`、`usage/cost`）。
2. **健壮性**：限流重试、断点续跑（按 `question_id` 幂等）、超时、成本上限（每模型可设 max_tokens 与总预算）、错误/解析失败单独计数并报告。
3. **解析鲁棒性**：现有 `_parse_letter` 取第一个 A–D；对 reasoning 模型要兼容「思考链 + 最终答案」两种返回，必要时强制 `final answer: X` 模板或关 thinking（DeepSeek 已关）。
4. **配置去 NER 化**：新增 `MCQ_EVAL_*` 环境变量或 `config/models.yaml`，与 `TEXT_NER_*` 解耦，避免语义误导。

### 1.4 提示策略（默认，先探针后迭代）

- **零样本 + 直接答案**：沿用现有 prompt（临床单选、只回 A–D 字母），`temperature=0`。
- **选项确定性 shuffle**：保持 `question_id` 种子 shuffle（避免 gold 恒为 A 的位置偏差），这是现有正确做法，跨模型统一。
- **reasoning 模型处理**：默认关 thinking（保证 latency/成本可比）；另设一个「thinking 开」对照臂，看临床决策是否因推理收益（文献提示推理收益与任务/信息量强相关）。
- 后续可选：few-shot（各维 3–5 例、用 dev 集校准）、self-consistency（sampling 多次投票，仅 reasoning 臂）。
- **只发短主诉描述 + 选项，不发 MIMIC 自由文本/note/标识符**——维持现有数据最小化原则。

### 1.5 指标与统计

- 主指标：**每维度 / 子任务准确率** + 分层（检查的 imaging/clinical_order/laboratory 三层；治疗 T1/T2/T3）。
- 不确定性：**Wilson 95% CI**（当前 n 很小：诊断 24、转诊 33，CI 很宽，必须报告，不能只报点估计）。
- 显著性：模型间 **配对 McNemar / 配对 bootstrap**（同一题集多模型配对，天然配对设计）。
- 辅助：top-3 准确率、解析失败率/弃答率、每 token 成本、每正确题成本。
- **关键诚实项**：n 过小（尤其诊断/转诊）时只做描述性对比，不下「显著优于」结论；探针结论只能是「该维能否区分模型」。

### 1.6 运行矩阵与成本/时间

- 规模：221 题 × ~10–15 模型 ≈ 2,200–3,300 次调用，单题 max_tokens=64，**token 成本可忽略**（远低于文本 NER 全量）。
- 真正成本是**人工**：选型登记、结果审阅、错误分析（见 §2）。
- 建议跑序：先 3 个代表性模型（1 闭源旗舰 + 1 国产 + 1 reasoning）试跑 221 题 → 看维度灵敏度与解析质量 → 再铺开到全名单。

### 1.7 污染与盲测防护

- 探针用 `validated_rank1`（dev+val 派生），**不碰 `final_test`**；`final_test` 只在冻结后、发布前盲测一次（项目已确立此纪律，多模型阶段必须继续遵守）。
- 每个模型调用记录 `prompt_hash` + 题目哈希，保证可复现、可审计。

## 2. 需要人工审核 / 负荷清单

> 分「必须先做的闸门」和「可并行的审核」两类；每条给出负荷量级与当前进度。

### 2.1 必须先做（阻塞任何「正式榜单」声称）

| # | 审核项 | 当前进度 | 负荷量级 | 说明 |
|---|---|---|---|---|
| 1 | **跨批归一化 100 条试审** | 18/100，reviewer 为占位值 | 中（需稳定 reviewer 重做剩余 ~82 条） | 冻结检查候选目录前的最后一个上游质量门禁；当前 18 条决定不可视为完成 |
| 2 | **文本 NER 人工 A/B 双标 + 第三人裁决** | A/B/裁决日志均为 0 | 高（200 份 pilot 双标 + 裁决；出院小结另需 event-frame 支路） | 解锁 evaluation 的前置；模型输出不能反向替代人工 gold |
| 3 | **P3 临床审核冻结清单逐项裁决**（`clinical-review-freeze-checklist.md`） | 六组占位值待裁 | 中 | 含检查白名单/panel、诊断两可与症状黑名单、治疗「急性 vs 慢病续方」与 condition 空间、转诊科室码 |
| 4 | **合规确认：向外部 API 发送内容的边界** | 未完成（README 明列） | 低（一次性签核） | 多模型跨多家厂商前必须锁定「短主诉+选项是否属受限文本」的结论 |

### 2.2 可并行的审核（不阻塞探针，但阻塞正式发布）

| # | 审核项 | 负荷量级 | 说明 |
|---|---|---|---|
| 5 | 各维 gold 临床语义逐题审（诊断两可主诉、治疗相邻品类翻转、转诊相邻科室、检查 panel 粒度） | 高 | 决定是否「允许多 gold / 非对称计分」 |
| 6 | 最终 MCQ 题干+选项+干扰项临床审核 | 高 | 文献锚：EHRNoteQA 中 33.8% 正确答案被改、24% 题干被改——干扰项质量是本 bench 的隐性成本 |
| 7 | 干扰项生成策略审（当前「取 pool 前 3 个非 gold」过于 naive） | 中 | 需层次化「同层混淆项」而非明显错误项 |
| 8 | final_test 发布前一次性盲测复检 | 低（只读一次） | 冻结后执行 |

### 2.3 多模型评测本身的轻量人工

- 模型选型与 API 登记、结果抽查（每题必看错题，尤其诊断 24 题全量人工可负担）、错误类型归因（知识缺失 / 干扰项误导 / gold 本身有误）。

## 3. 可优化点（分评测 harness 与 bench 本身）

### 3.1 评测 harness 层

1. **收敛散落 evaluate.py → 统一多 provider 评测器**（§1.3，最高杠杆）。
2. **指标升级**：补 Wilson CI / bootstrap、配对检验、top-3、解析失败率、成本——现在只有 point accuracy + 分层。
3. **配置去 NER 化**：`TEXT_NER_*` 用于 MCQ 评测名不副实，拆出 `MCQ_EVAL_*`。
4. **断点续跑 + 幂等 + 限流 + 成本上限**（现无）。
5. **reasoning 模型兼容**（thinking 开关 + 解析）。
6. **prompt 版本控制**：prompt 内容 hash 进 run manifest（题目哈希已有，prompt 哈希补上）。

### 3.2 bench 本身层

1. **干扰项生成**：从「pool 顺序取前 3」改为**层次化混淆项**（同解剖系统/同表现簇），专家确认「该时点可辩」——这是提升区分度的主要空间。
2. **题量不足**：诊断 24、转诊 33、检查 84，冻结后扩容是正式榜单的前提；探针阶段先用现有题量。
3. **双 gold / 非对称计分**：两可主诉（HF vs 肺炎/脓毒症）、相邻科室/品类翻转——唯一答案在低共识区天然稀缺（survey：多专科合理性 ~10pp）。
4. **condition 空间净化**：治疗维 `abnormal mri/labs/clotted fistula/elevated troponin` 是检验/事件而非主诉，应从主诉空间过滤（已列入冻结清单，属 P3 待裁）。
5. **品类映射升级**：substring（~78% 覆盖）→ RxNorm/ATC 精确映射（治疗维），消除相邻品类翻转。
6. **泄漏/去标识扫描**：诊断维题干做诊断词去标识扫描；snapshot 层未来信息泄漏审计（正式链路）。
7. **离院维补齐**：F1 四子轴需文本 NER/RE 支路 + 以「出院诊断」为键（当前正则只抽到 ~5% 随访时间窗）；规范主榜缓行香港阶段。

---

## 4. 建议执行顺序（一句话）

1. **先锁合规**（§2.1 #4）→ 2. 用现有 221 题跑 **3 模型试跑**（§1.6）→ 3. 视维度灵敏度决定是否铺开全名单 → 4. 期间并行推 **归一化 100 条试审 + P3 冻结清单**（这是正式榜单的唯一关键路径）→ 5. 冻结后扩容题量 + 层次化干扰项 + 双 gold，再跑正式多模型榜单。

> 一句话总结：多模型评测「现在能做、但只能当探针」；真正的瓶颈不在模型调用（成本可忽略），而在 **人工 gold 冻结 + 干扰项质量 + 合规签核** 三个闸门。
