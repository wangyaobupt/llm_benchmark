## 0. 下一步是什么

抽取层已经把 MIMIC 原值投影成一行一次住院。标准化层只做一件事：

> 把同一临床含义的不同写法收成可比较的术语和单位，并给症状/主诉一套稳定概念名，**不改写病历事实，不覆盖抽取文件**。

```text
visits.json（冻结，10,000 行原值）
        │  N0  输入指纹 + 行数对账
        ▼
term inventory（每个字段的原始术语/单位及其频次）
        │  N1  确定性规则 + 已审核同义词表
        ▼
visits_standardized.json / .csv
  · 原文字段逐字节保留
  · 另增 *_normalized / 单位换算 / 症状概念列表
        │
        ▼
review_queue.jsonl（映射不了的高频项，人工或离线候选，不在运行时猜）
```

本层结束后才允许讨论题干用哪个标准名。标准化未过门禁，不出题。

## 1. 与仓库里其他「标准化」的边界

| 轨道 | 输入 | 本计划是否使用 |
|---|---|---|
| `event_pipeline.event_normalization` | 27M 清洗事件 | **不作为输入**。可借用其单位别名表 `UNIT_ALIASES` 和「 unresolved 进审核队列、运行时不准新建映射」 |
| `rwd_pipeline` 17 列标准化 | 旧 CSV | 历史规范，**不跑、不接产物** |
| `text_ner_v2` | 聚合事件上的出院小结 NER | 本阶段**先不做**全文 NER。症状只从已切开的主诉/体格等短字段抽概念；HPI/全文仍原样保留 |
| 检查选择 v3.1 | 冠心病事件 corpus | 并行，不改 `protocol.yaml` |

标准化对象是 **visit 行文件的 45 个结果列**，不是 MIMIC 全表事件。

## 2. 原则（硬约束）

1. **抽取文件只读。** 禁止覆盖 `visits.json` / `visits.csv`。派生产物另目录。
2. **原文与标准名并存。** 标准化对象必须能看见抽取原值。禁止「只留下标准名、丢掉 Chest pain / CP / 胸痛 源串」。
3. **确定性优先。** 正式 transform 只查冻结映射表 + 单位换算表。不得在跑 10,000 行时调用 LLM 现编同义词。
4. **不确定就 unresolved。** 不猜、不上升到更粗的上位概念来「凑唯一答案」。`unresolved` 可出条件题干，不得单独当标准答案键。
5. **换算必须可逆。** 华氏→摄氏、`mg/dl`→`mg/dL` 这类要写清规则；`mg/dL`↔`mmol/L` 没有锁定换算因子就只做别名统一，不改数值。
6. **不翻译。** 标准名用英文（与 MIMIC / 题型规范一致）。不把 Discharge Summary 改成中文。
7. **不改写叙事。** `history_of_present_illness`、`brief_hospital_course`、`discharge_note_full`、`discharge_record` 正文逐字节复制。症状统一发生在**派生概念列表**上，不发生在改写后的段落上。
8. **否定与时间状态不丢。** 「denies chest pain」不得变成阳性 `chest_pain`。
9. **不跨 ICD-9/10。** 诊断/操作继续带着源版本；标准名用字典 `long_title` 的空白规范化，不做 crosswalk。
10. **患者原文不进 git，也不默认送在线 LLM。** 若要用模型生成映射候选，只上传**去重后的术语串 + 频次 + 字段名**，禁止上传整份病历。

## 4. 字段分工：改什么、原样复制什么

### 4.1 原样复制（标准化层不得改字）

| 列 | 理由 |
|---|---|
| `subject_id`, `hadm_id` | 主键 |
| `age_at_encounter`, `sex` | 抽取已是 int / `M`/`F` |
| `admission_type`, `admission_location`, `discharge_location`, `ed_disposition` | 受控词表，保留 MIMIC 原码 |
| `history_of_present_illness` | 叙事；症状概念另列 |
| `social_history`, `physical_exam` | 长文本；体格异常另做可选实体列表 |
| `medications_on_admission`, `discharge_medications` | 自由文本药单，先做实体清单、不改段落 |
| `brief_hospital_course`, `discharge_condition`, `discharge_record`, `discharge_note_full` | 出题隔离与原文恢复 |
| `discharge_diagnosis` | 文本章节；编码诊断走 `primary_*` / `other_diagnoses` |
| `vitals_source` | 来源标记 |
| `transfers`, `service_path` | 路径事实 |

### 4.2 要统一的（本计划核心）

按用户要求分成三块：**术语、单位、症状/相关描述**。

#### A. 术语（同一概念一个标准英文名）

| 源列 | 标准产物 | 映射键 |
|---|---|---|
| `investigations.laboratory[].label` + `fluid` + `category` + `itemid` | `standard_test_name` 如 `Creatinine, Blood` | `itemid` 优先，名称作校验 |
| `investigations.radiology[].exam_name` | `standard_exam_name` 如 `Chest radiography` | 规范化 exam_name |
| `investigations.cardiology/respiratory[].order_subtype` | `standard_order_name` | subtype + 排序后的 poe_detail |
| `medications[].drug` | `standard_ingredients[]`（活性成分，英文） | 规范化药名；商品名无成分则 `unresolved` |
| `medrecon[].name` | 同上，字段上下文=medrecon | 不与住院处方混键 |
| `procedures[].procedure_name` + `icd_code` + `icd_version` | `standard_procedure_name` | 三者；不跨版本 |
| `primary_diagnosis_name` + code + version | `standard_diagnosis_name`（通常=空白规范化后的 long_title） | 不跨 ICD |
| `other_diagnoses[]` | 同主诊断规则的名称数组 | 按源序 |
| `ed_diagnoses[].icd_title` | `standard_ed_diagnosis_name` | 急诊标题+code |
| `primary_service` | `standard_service_name`（`MED`→`Medicine`） | 科室代码表 |
| `allergies` | `allergy_concepts[]`（含 NKA 作为合法概念，不是缺失） | 行内切分 |
| `rhythm` | `standard_rhythm`（`Sinus Rhythm` 大小写/空白） | 别名表 |
| `poe_lab_imaging` | **本版不把医嘱猜成具体检验名**（与抽取 P1 一致） | 仅空白规范化 |

#### B. 单位与数值

| 源 | 规则 |
|---|---|
| `temperature` | 抽取是华氏原值。标准化写 `temperature_c` = `(F-32)*5/9`，保留 `temperature_f`。单位标签 `°C` / `°F`。无法解析则两套都 null |
| `heartrate` | 单位 `bpm`（标注，不改值） |
| `resprate` | `/min` |
| `o2sat` | `%` |
| `sbp`/`dbp` | `mmHg` |
| `acuity` | ESI 1–5，无量纲 |
| lab `valueuom` | 只做**别名统一**（`mg/dl`→`mg/dL`，`mm hg`→`mmHg`），数值与参考范围**不缩放**，除非映射表写明可逆因子 |
| lab `valuenum` | 保留；标准化后的 `normalized_unit` 与原单位一起存 |
| 处方 `dose_unit_rx` / `prod_strength` | 别名统一；`1 tablet` 与 `1 mg` 不得合成一个数 |
| 禁止 | 静默把 mmol/L 的钠换成 mg/dL；禁止编造缺失单位 |

单位别名优先复用 `event_normalization.terminology.UNIT_ALIASES`，拷贝进本模块并**锁版本**，不在运行时改事件层那张表。

#### C. 症状与相关描述

目标：题干能写「Chest pain, dyspnea」而不是 100 种缩写，同时能回溯原句。

| 源列 | 产物 | 做法 |
|---|---|---|
| `chief_complaint` | `chief_complaint_concepts[]` | 按逗号/`/`/换行切开 → 空白规范化 → 症状同义词表。保留 `source_span`（原短串） |
| `ed_chief_complaint` | `ed_chief_complaint_concepts[]` | **独立映射表**，不与 DS 主诉混用缩写（ED 的 `SOB` 与 DS 段落里的缩写语境不同） |
| `history_of_present_illness` | `hpi_symptom_mentions[]`（可选，第二波） | 本波**默认不做全文抽症状**，避免和 NER 抢。若试点 100 显示主诉过粗，再开规则/词典匹配，不改写 HPI 正文 |
| `physical_exam` | `exam_finding_concepts[]`（可选，第二波） | 同上 |
| `allergies` | 见术语表 | `No Known Allergies / Adverse Drug Reactions` 是有效概念 `nka`，不是空 |
| 否定 | `polarity`: `asserted` / `denied` / `uncertain` | 「denies chest pain」→ `chest_pain` + `denied`，不得当阳性主诉 |

第一波（必须落地）只强制：`chief_complaint` + `ed_chief_complaint` + 过敏概念。HPI/体格的症状清单列为 M3 闸门后的可选扩展，避免标准化层变成不完整 NER。

## 5. 标准名形状（派生列，不删原列）

每行仍是一次住院。输出 = 原 45 列（字节级与输入 JSON 对应字段一致）+ 下列派生键。

```json
{
  "chief_complaint": "CP, SOB",
  "chief_complaint_concepts": [
    {
      "source": "CP",
      "standard": "Chest pain",
      "concept_id": "symptom:chest_pain",
      "polarity": "asserted",
      "status": "mapped/exact"
    },
    {
      "source": "SOB",
      "standard": "Shortness of breath",
      "concept_id": "symptom:dyspnea",
      "polarity": "asserted",
      "status": "mapped/exact"
    }
  ],
  "temperature": 98.6,
  "temperature_f": 98.6,
  "temperature_c": 37.0,
  "vitals_units": {
    "temperature": "°C",
    "heartrate": "bpm",
    "resprate": "/min",
    "o2sat": "%",
    "sbp": "mmHg",
    "dbp": "mmHg"
  },
  "investigations_normalized": {
    "laboratory": [
      {
        "itemid": 50912,
        "source_label": "Creatinine",
        "standard_test_name": "Creatinine, Blood",
        "fluid": "Blood",
        "results": [
          {
            "valuenum": 1.5,
            "source_unit": "mg/dL",
            "normalized_unit": "mg/dL",
            "unit_status": "mapped/exact",
            "flag": "abnormal"
          }
        ]
      }
    ]
  },
  "medications_normalized": [
    {
      "source_drug": "VANCOMYCIN",
      "standard_ingredients": ["Vancomycin"],
      "status": "mapped/exact"
    }
  ]
}
```

`normalization_status` 只允许：

```text
mapped/exact | mapped/converted | unresolved | not_applicable
```

`mapped/converted` 仅用于有锁定公式的单位换算（如 °F→°C）。

## 6. 管线阶段

```text
N0  冻结输入：校验 10,000 行、45 键、抽取 sha256
N1  术语盘点：按字段输出 term_inventory.jsonl（term, field, count）
N2  装载冻结映射：症状 / 检验名 / 影像名 / 药物 / 科室 / 单位别名
N3  应用映射 + 单位换算 → 10,000 行标准化 JSON
N4  未命中写入 review_queue（带频次）；缺映射表版本则整次失败
N5  写出 visits_standardized.json / .csv；验收；不覆盖抽取
```

可断点续传：与抽取同一套 identity + 分片（建议 1,000 行/片）。`visits.json` 已是 10k 行，按 `hadm_id` 稳定顺序分片即可。映射表变更必须改 mapping_version，换输出目录，禁止在旧目录混跑。

### 6.1 症状切分规则（主诉，第一波）

对 `chief_complaint` / `ed_chief_complaint`：

1. 换行归一；按 `,`、`;`、`/`、` and `（两侧有界）切开，但 **不切** `N/A`、`s/p` 内部（用小否定表）。
2. 去首尾空白，合并连续空白，大小写折叠仅用于查表，标准名输出 Title/词典形式。
3. 命中冻结别名 → `mapped/exact`。
4. 未命中：若去标识后仅为 `___` → `not_applicable`；否则 `unresolved`，原串进入 review_queue。
5. 切出空段丢弃。整字段空（抽取已保证 DS 主诉非空）不应出现。

种子别名（写入映射文件，允许后续只增不改语义）：

```text
cp, c/p, chest pain, chest pressure, chest tightness → Chest pain
sob, s.o.b., shortness of breath, dyspnea, dyspnoea → Shortness of breath
n/v, nausea and vomiting, n&v → Nausea and vomiting
abd pain, abdominal pain, belly pain → Abdominal pain
ha, headache → Headache
loc, syncope, passed out → Syncope
weakness, generalized weakness → Weakness
```

ED 与 DS 两张表分开；同一缩写若在两字段意义可能不同，不得强行合并。

### 6.2 检验与单位

- 名称：`itemid` 已连接 `d_labitems`。标准名建议 `"{label}, {fluid}"`，与旧 RWD 规范一致。
- 单位：`normalized_text(unit)` 查 `UNIT_ALIASES`。无别名 → `unresolved`，数值仍保留。
- 参考范围跟着原单位走；单位只改写法时范围数值不变。

### 6.3 药物

- 第一波：大小写/空白规范化 + 小表通用名（Vancomycin、Aspirin 等高频）。
- 复方：映射可返回多个 ingredient，顺序按映射表。
- 无把握：`unresolved`，保留 `source_drug`。
- 不在本波做 RxNorm 全库；那是独立字典工程。

### 6.4 科室

锁定一张 `services` 代码表（抽取规范已有 MED/CMED/SURG…）。未知代码 `unresolved`，不删原码。

## 9. 验收门禁

同时满足才算标准化完成：

1. 输入 10,000 行与输出 10,000 行 `hadm_id` 一一对应、同序。
2. 原 45 列与输入 JSON **逐字段相等**（嵌套对象 canonical JSON 相等）。
3. 每个非空待映射项的 `status` ∈ 允许集合；非 `not_applicable` 的项要么在 mappings 有记录，要么在 review_queue。
4. 所有 `mapped/converted` 可用公式反算回原值（温度允许 0.05°C 误差）。
5. `chief_complaint_concepts` 对 10,000 行主诉的 mapped 比例写入报告；不设虚假 100% 目标。
6. 验收 JSON 不含患者原文。
7. 标准化文件不得出现 `lineage`/`ds_note_id`（与抽取交付合同一致）；过程 working 可含。

**未过门禁不得出题。** review_queue 里的高频症状未审完，题干不得用「统一后的症状名」冒充已审核。

## 11. 与出题层的接口（本计划仍不出题）

出题引擎以后应：

- 题干症状优先读 `chief_complaint_concepts.standard`（仅 `mapped/*` 且 `polarity=asserted`）
- 生命体征展示用 `temperature_c` 等标准单位，必要时脚注原华氏
- 检验选项用 `standard_test_name`，仍可回溯 `itemid`
- **继续遵守信息隔离**：标准化不会把诊断写进题型①题干，因为诊断列仍在、只是多了标准名

`discharge_note_full` 仍然禁止当题干。

## 12. 体积与时间（粗估）

| 项 | 估计 |
|---|---|
| 10k 标准化 JSON | 略大于抽取 JSON（多派生列），约 +10–30% |
| 盘点 + 映射应用 | 内存远小于漏斗载入出院小结；**分钟级到十几分钟**，不是再扫一遍 `labevents.csv.gz` |
| 续跑 | 按 1,000 行分片；映射表变了必须换目录 |

## 13. 一句话合同

> 在不覆盖 10,000 例抽取结果的前提下，用冻结的确定性映射统一检验名、药名、科室、单位写法和主诉/急诊主诉的症状概念；华氏体温换算为摄氏并保留原值；长文本病历不改写。映射不了的进审核队列。未过门禁不出题，gold 仍为 0。
