# 出题 Visit 时间线合并与 10,000 例规则挖掘计划

> **版本**: v1.0  
> **日期**: 2026-08-20  
> **状态**: 代码已落地（`mcq_visit_timeline` / `mcq_visit_mining`）；10k 跑数由操作者执行  
> **评测状态**: `exploratory_unreviewed`；`gold = 0`  
> **本轮明确不做**: 出院小结 NER 全量、题目生成、人工 gold、v3.1 检查选择 formal 升级  
> **上游（只读，不覆盖）**:
> - 时间点补齐：`data/derived/mcq_visit_extract/random10k_dev20_times/visits.json`（`mcq_visit_extract/3.1.2`，10,000 行）
> - 标准化：`data/derived/mcq_visit_standardize/random10k_dev20_v1.0.9/visits_standardized.json`（主诉 mapped ≈ 95.8%）
> - 抽取指纹：冻结 `random10k_dev20/visits.json` 只作身份对账，不作为本层时钟源  
> **方法对照**: [`MCQ 出题逻辑.md`](../../mcq_generation/MCQ%20出题逻辑.md)；[`RWD Clinical Benchmark 检查检验选择题生成设计.md`](../../mcq_generation/RWD%20Clinical%20Benchmark%20检查检验选择题生成设计.md) §7；冠心病 EDA 的 CBC/BMP 基线陷阱；V2 全住院窗口失效结论。本计划**不**消费 `event_pipeline` Parquet，**不**改 `config/investigation-selection/protocol.yaml`。

## 0. 下一步是什么

NER 先停。现有结构化字段、标准名和时间点已经够做两件事：

1. **把一次住院里散落的数组收成一条可查询时间线**（时钟 + 标准名）。
2. **在这 10,000 例开发池上做五类题型的 X→y 规则挖掘**（统计定答案，不出题）。

```text
times/visits.json          标准化 visits_standardized.json
（3.1.2 时钟，只读）         （1.0.9 标准名，只读）
        │                              │
        └──────── T0 身份对账 ─────────┘
                        │
                        ▼
        T1  按 hadm_id 对齐，投影事件 + 接上标准名
                        │
                        ▼
        visit_events.parquet + visit_timelines.jsonl
        presentation_facts.jsonl
                        │  M0 目录 / 窗口 / 生命体征旗标
                        ▼
        M1  按题型做事务（features + outcomes，带隔离）
                        │
                        ▼
        M2  10,000 例全量 X→y（8 道统计门槛）
                        │
                        ▼
        accepted / rejected 规则 + 验收报告（无病历原文）
                        │
                        ▼
        不出题。不把 accepted 规则当 gold。
```

两层都结束后，数据状态仍是 `exploratory_unreviewed`。规则表可以告诉下游「哪类 X 在这 1 万例里站得住」，但不能送审、不能发布、不能当标准答案。

## 1. 为什么现在做这两步、为什么先不做 NER

### 1.1 已经齐的输入

| 产物 | 用途 | 缺口 |
|---|---|---|
| 冻结抽取 10,000 行 | 身份、原文 45 列 | schema `3.1.0`，缺用药起止、化验/影像 `storetime`、操作 `chartdate` |
| 时间点补齐 10,000 行 | **本层时钟权威** | 无标准名；处方 ≈99.85% 有 `starttime`；化验 ≈99.46% 有 `storetime`；影像/操作/medrecon 时间覆盖 100% |
| 标准化 v1.0.9 | **本层名称权威** | 主诉概念 mapped 12,194 / 12,732（95.77%）；`review_queue` 已空；**规范化检验结果里没有 `charttime`/`storetime`**；用药规范化对象没有 `starttime` |
| NER 试点 100 | 出院小结 span | 未覆盖 10k；本轮不消费 |

实测同一 `hadm_id` 在时间点补齐与标准化文件中对齐。标准化层把检验结果收成 `valuenum` + 单位 + `flag`，时钟被丢掉了。因此时间线**必须**用补齐文件做事件，再用标准化文件按键贴标准名，不能只读其中一份。

### 1.2 不做 NER 的代价（写进合同，不事后补洞）

没有出院小结 NER，本轮条件特征只能来自：

- 已切开的主诉 / 急诊主诉概念（mapped 才进 X；`unresolved` / 过长稀有串进不了频繁项）
- 人口学、入院类型、过敏概念
- 分诊生命体征及其定性旗标
- 时间线上、窗口内、且隔离规则允许的结构化事件

进不了本轮 X 的：HPI 全文症状、体格异常、入院前用药自由文本、既往史自由文本、出院指导自由文本。题型⑤ 因此只挖结构化离院去向，不挖 Discharge Instructions 句子。

### 1.3 必须避开的三条旧路

| 旧路 | 为什么不能当本层输入或实现 |
|---|---|
| `event_pipeline` 27M 事件 / 冠心病 1,000 例 corpus | 另一条轨道；队列、时钟合同、eligibility catalog 都不是这 10k 随机 Visit |
| `investigation_selection.mining` 直接 import | 它挖的是 `decision_document` + `candidate_class`；本层是 visit 事务 + 五类 y。公式可**抄**（Wilson / Fisher / BH / bootstrap），包不能耦 |
| 旧 V2 / `archived/phenotype` | 后验 ICD、全住院目标窗口、类别级 Lab 医嘱、split 泄漏；禁止进入新统计 |

## 3. 原则（硬约束）

1. **上游只读。** 禁止覆盖抽取、时间点补齐、标准化三个目录。
2. **时钟与名称分源。** 时钟只来自 `3.1.2` 补齐文件；标准名只来自 v1.0.9。对不上键就 `unresolved`，不猜。
3. **一行一次住院的身份不变。** 必须恰好 10,000 个唯一 `hadm_id`，集合与抽取 `selection.jsonl` 一致。
4. **事件不发明医嘱。** 化验项目名在结果层，不是 POE `Lab`。POE 的 `order_type=Lab` 只能标 `category_only`，不得当题型① 的具体 y。
5. **后验不进题型① 的 X。** 诊断、检查结果、住院处方、操作、出院记录不得作为检查选择的条件。
6. **全住院窗口不得当题型① 的 y。** 目标必须落在声明的首波窗口内。这是 V2 失效的直接教训。
7. **不确定就丢。** 缺时间的事件保留并打 `time_missing`，不参与窗口内 outcome；不把 `chartdate` 假装成秒级。
8. **确定性。** 无 LLM。相同输入 + 相同 config → 相同 `event_id` / `rule_id`。
9. **患者原文不进 git、不进验收正文。** 报告只含计数、分布、规则摘要。
10. **非正式金标准。** accepted 规则也只是 `exploratory_unreviewed`。

## 5. 阶段 T：时间线合并

### 5.1 要解决的问题

一次 Visit 现在是「字段口袋」：化验在 `investigations.laboratory[].results[]`，影像在 `radiology[]`，用药在 `medications[]`，转科在 `transfers[]`。挖掘和以后出题都需要：

> 在时刻 T，哪些事实已经发生、哪些结果已经可见。

合并不是再做一套 `event_pipeline`。它只投影这 10,000 行已经抽出的数组，加上住院时钟，按时间排序。

### 5.2 就诊原点

每个 Visit 计算一次，写入 timeline 头，不 coalesce 成一个模糊时间：

| 字段 | 规则 |
|---|---|
| `admittime` | 住院开始（补齐文件，10,000/10,000 非空） |
| `presentation_origin` | 有 `ed_intime` 用急诊入室，否则 `admittime` |
| `presentation_origin_basis` | `ed_intime` 或 `admittime`（原样记录，禁止混写） |
| `dischtime` / `deathtime` | 住院结束；死亡时间有则另记，不替代出院 |

主诉、急诊主诉、分诊生命体征、过敏、年龄性别**没有原生事件时间**。它们绑定到 `presentation_origin`，记 `time_precision=bound`。禁止给分诊主诉编造 `charttime`。

### 5.3 事件种类与时钟

| `event_kind` | 源 | `occurrence_time` | `available_time` | 精度 |
|---|---|---|---|---|
| `lab_resulted` | `investigations.laboratory[].results[]` | `charttime`（采集代理） | `storetime`（结果可见） | datetime |
| `radiology_reported` | `investigations.radiology[]` | `charttime` | `storetime` | datetime |
| `cardiology_ordered` | `investigations.cardiology[]` | `ordertime` | `ordertime` | datetime |
| `respiratory_ordered` | `investigations.respiratory[]` | `ordertime` | `ordertime` | datetime |
| `poe_lab_imaging` | `poe_lab_imaging[]` | `ordertime` | `ordertime` | datetime；Lab 几乎一定是 `category_only` |
| `medication_prescribed` | `medications[]` | `starttime` | `starttime` | datetime；这是处方不是 eMAR |
| `procedure_recorded` | `procedures[]` | `chartdate` 当日 00:00 | 同左 | **date**；不得当秒级决策点 |
| `medrecon` | `medrecon[]` | `charttime` | `charttime` | datetime；入院前核对，不是住院处方 |
| `transfer` | `transfers[]` | `intime` | `intime` | datetime |
| `service_transfer` | `service_path[]` | 源里的转科时间 | 同左 | datetime |
| `encounter_admit` / `encounter_discharge` / `encounter_ed_in` / `encounter_ed_out` | 住院/ED 时钟 | 对应字段 | 同左 | datetime |
| `rhythm_charted` | `rhythm` + `rhythm_charttime` | `rhythm_charttime` | 同左 | datetime；10k 里仅 469 例有时间 |
| `vitals_triage` | 生命体征列 | `presentation_origin` | 同左 | bound |
| `complaint_bound` | 主诉/急诊主诉概念 | `presentation_origin` | 同左 | bound |

禁止：

- 用化验 `storetime` 当「开了这个检查」的时间。
- 把 POE `Lab` 与 `labevents` 按时间 join 成一条医嘱。
- 使用 eMAR / ICU `procedureevents`（抽取合同明确未抽）。
- 出院小结 `charttime`（那是 lineage，不是结果列）。

相对时间（写入每条事件，便于窗口过滤）：

```text
hours_from_admit         = (occurrence_time - admittime) / 3600
hours_from_presentation  = (occurrence_time - presentation_origin) / 3600
```

解析失败或源值为空 → 时间字段 null，`time_missing=true`，该事件仍落盘但不进入任何「窗口内 outcome」。

### 5.4 标准名怎么贴上去

时间点补齐行保留源名；标准化行保留 `*_normalized`。对齐键必须与抽取/补齐已用的 core 一致：

| 域 | 对齐键 | 贴上的标准字段 |
|---|---|---|
| 化验 | `itemid` | `standard_test_name`（如 `Creatinine, Blood`） |
| 影像 | 规范化 `exam_name` | `standard_exam_name` |
| 心内/呼吸 POE | `order_subtype` + 排序后的 `poe_detail` | `standard_order_name` |
| 用药 | 抽取 `medication_core` 七键 | `standard_ingredients[]` |
| 操作 | `icd_code` + `icd_version` | `standard_procedure_name` |
| 主诊断 / 其他诊断 / 急诊诊断 | 已在 Visit 级 | `standard_diagnosis_name` 等，进 presentation/outcome 表，不伪造诊断事件时间 |
| 科室 | Visit 级 `primary_service` | `standard_service_name` |
| 主诉 | Visit 级概念数组 | 只进 `presentation_facts` |

一对多（同一 `itemid` 多次结果）按结果行展开，不在时间线层聚成「一次化验」。同一处方多行按源数组一行一事。

`mapping_status` 随标准名拷贝。`unresolved` 的名称可以出现在时间线上，但 **M1 不得把它们当作可挖掘的 y 或 X**。

### 5.5 `event_id`

```text
event_id = sha256(hadm_id | event_kind | occurrence_time | source_field | 稳定业务键)[:24]
```

业务键：化验=`itemid`+`charttime`+`value`+`valuenum`；影像=`exam_name`+`charttime`；用药=七核+`starttime`。禁止用 Python `id()` 或写入顺序。

### 5.6 正式交付（timeline）

目录：`data/derived/mcq_visit_timeline/random10k_dev20_v1.0.0/`（试点可 `pilot100_...`）。

| 文件 | 形态 | 内容 |
|---|---|---|
| `visit_events.parquet` | 一行一事件 | 查询、窗口过滤、计数；约 2.3M 行量级（化验结果 1.79M + 处方 0.36M + 其余） |
| `visit_timelines.jsonl` | 一行一次住院 | 头信息 + 按 `(occurrence_time, event_kind, event_id)` 排序的 `events[]` |
| `presentation_facts.jsonl` | 一行一次住院 | 人口学、主诉概念、生命体征、过敏、入院类型、就诊原点 |
| `manifest.json` | JSON | 输入指纹、schema、计数、覆盖率 |
| `summary.json` | JSON | 无原文的验收计数 |

Visit 头与事件都**不**复制 HPI / 出院小结全文。需要原文时回读冻结抽取。

下游怎么读（执行合同）：

- 人抽查某一例 → 只打开 `visit_timelines.jsonl`（嵌套时间线）。
- `mcq_visit_mining` → 只打开 `presentation_facts.jsonl` + `visit_events.parquet`。**不打开** `visit_timelines.jsonl`。
- 三份是同一批 Visit 的不同投影，不是互相截取的片段。时间线目录 `status=complete` 后即可开挖掘，不必再跑抽取或标准化。

Schema 名：`mcq_visit_timeline/1.0.0`。

### 5.7 时间线成功标准

1. 10,000 个 `hadm_id` 与抽取 selection 集合相同。
2. 化验事件数与补齐 `lab_result_rows=1,785,178` 对账（允许因空值过滤写进 summary 的差，差必须解释）。
3. 处方事件数对账 `medication_rows=363,212`。
4. `lab_resulted.available_time` 非空率与补齐 `lab_storetime_rate=0.9946` 一致到 0.1pp。
5. 每个 Visit 的事件按时间稳定排序；`hours_from_admit` 在可解析事件上无 NaN。
6. 不写入上游目录；验收报告无患者原文。

## 6. 阶段 M：规则挖掘（10,000 例全量）

输入目录就是上一节的 timeline `--output-dir`。CLI `--timeline-dir` 指向它。挖掘合同来自题型 1 的 Stage 3–4，推广到五类 y，但**本轮停在规则表**。不跑干扰项锁定、不跑 LLM、不跑审核。

### 6.1  Universal 事务形状

```text
visit_key     = sha256(subject_id | hadm_id)   # 仅本地，不写进规则展示
hadm_id       = 源键（本地产物可保留，报告与规则 JSON 对外字段用 visit_key）
family        = type1_investigation | type2_diagnosis | type3_medication
                | type3_procedure | type4_service | type5_disposition
features[]    = {feature_id, feature_type, display_name}
outcomes[]    = {outcome_id, outcome_name, family, grain}
```

`feature_id` / `outcome_id` 稳定排序后哈希进 `rule_id`。同一 Visit 内 features、outcomes 去重。

### 6.2 特征类型（无 NER 版）

| `feature_type` | 来源 | 准入 |
|---|---|---|
| `age_band` | `age_at_encounter` → `18-39` / `40-49` / `50-59` / `60-69` / `70-79` / `80+` | 每 Visit 至多一个 |
| `sex` | `M` / `F` | 至多一个 |
| `admission_type` | 原码 | 可选条件，不是必需症状 |
| `symptom` | `chief_complaint_concepts` 与 `ed_chief_complaint_concepts` 中 `status=mapped/exact` 且 `polarity=asserted` | **至少此类（或 sign/physiologic_flag/absent）之一才能组成合法 X** |
| `physiologic_flag` | 分诊生命体征按冻结阈值 | 见 §6.3 |
| `allergy` | `allergy_concepts` mapped；`nka` 是合法概念 | 题型③ 可进 X |
| `investigation_result_flag` | 窗口内、`available_time` 已知的化验定性（高/低/异常） | **仅题型②③**；禁止进题型① |
| `diagnosis` | 主诊断标准名或诊断组 | **仅题型③④⑤**；禁止进题型①② 的「当时诊断」（题型② 的 y 才是诊断） |

明确不做（本轮）：`sign`（体格未 NER）、HPI 症状、入院前药清单自由文本、`uncertain` / `not_mentioned`。

主诉概念若是整句稀有串（试点里出现过整段主诉被当成一个 concept），支持度会不够，Apriori 自然丢掉。不要在挖掘期用 LLM 再切。

### 6.3 生命体征旗标（写入 config，运行时不准改）

`config/mcq_visit_mining/vital-flags.yaml` 初值（exploratory，临床未审）：

| 旗标 | 规则 | 缺测 |
|---|---|---|
| `tachycardia` | `heartrate >= 100` | 不生成旗标 |
| `hypotension` | `sbp < 90` | 不生成 |
| `hypoxia` | `o2sat < 92` | 不生成 |
| `fever` | `temperature_c >= 38.0`（无摄氏则先用补齐华氏换算，与标准化同一公式） | 不生成 |
| `tachypnea` | `resprate >= 24` | 不生成 |

数值本身不进 features（年龄已分段）。旗标是定性 `physiologic_flag`。

### 6.4 题型家族：X / y / 窗口 / 隔离

窗口时钟一律相对 `presentation_origin`。配置在 `config/mcq_visit_mining/windows.yaml`。

#### 题型① 检查检验选择 — `type1_investigation`

> 给定就诊表现，真实数据里最可能被选择的检查是什么？

| | 合同 |
|---|---|
| X | `symptom` + 可选 `physiologic_flag` / `age_band` / `sex` / `admission_type`。**禁止**诊断、化验结果、处方、操作、POE 结果、出院 |
| y | 首波窗口内的检查概念（见 §6.5） |
| 窗口 | 默认 `[presentation_origin, +4h]`；`occurrence_time` 落在半开区间内。`time_missing` 不计 |
| 语义 | 「窗口内出现该检查结果/开单」是 **选择代理**，不是指南推荐，也不是 POE 项目级医嘱 |
| 索引 | 不用全住院；不用「该次住院任意时刻做过的所有化验」 |

#### 题型② 临床诊断 — `type2_diagnosis`

| | 合同 |
|---|---|
| X | 表现特征 + 窗口内**已可见**的检查结果旗标（`available_time <= index`） |
| y | `standard_diagnosis_name`；支持度不够的长尾 ICD 标题不进 y，进诊断组草稿或直接淘汰 |
| 窗口 | 默认表现后 24h 内可见的结果作为条件；y 仍是**出院主诊断** |
| 诚实标签 | `outcome_time_basis=discharge_icd_posthoc`。这不是「当时作出的诊断」。**不得当 gold** |

#### 题型③ 治疗 — `type3_medication` / `type3_procedure`

| | 合同 |
|---|---|
| X | 表现特征；**默认第一波不含出院诊断**（避免用后验诊断解释处方）。第二波 exploratory 可加诊断，产物打 `uses_posthoc_diagnosis` |
| y（药） | 窗口内 `medication_prescribed` 的 `standard_ingredients`（mapped）。出院带药文本不当 y |
| y（操作） | `procedure_recorded` 且 `chartdate` 在入院日或窗口日历日内；因精度是 date，单独家族，门槛可更严 |
| 窗口 | 默认处方 `starttime ∈ [presentation_origin, +24h]` |
| 隔离 | 不用 `discharge_medications` |

#### 题型④ 转诊科室 — `type4_service`

| | 合同 |
|---|---|
| X | 表现特征；exploratory 第二波可加诊断（同样打后验标记） |
| y | `standard_service_name`（Visit 级 `primary_service`） |
| 窗口 | 无事件窗；一个 Visit 一个 y |
| 注意 | `Medicine` 会极高基线，lift 门槛会杀掉大多数规则——这是预期，不是实现错误 |

#### 题型⑤ 离院去向 — `type5_disposition`

| | 合同 |
|---|---|
| X | 表现 + 可选诊断（后验标记） |
| y | `discharge_location` 原码（受控词表，不翻译） |
| 本轮不做 | Discharge Instructions 句子、随访计划、危险信号（需要 NER/分类） |

### 6.5 题型① 的检查目录（防止 CBC/BMP 再一次吞掉全部规则）

冠心病 EDA 已证明：若 y 是「住院期间任意化验」，大主诉的 rank-1 几乎全是 BMP/CBC，lift≈1，gap≈0，正式门槛通过率可以是 0。

本层目录分两套，**主分析只用 A**，B 只进 exploratory 附件：

**A. 主分析 y（`grain=specific`，可开立或可报告）**

| 家族 | 源 | 例子 |
|---|---|---|
| 影像 | `radiology_reported.standard_exam_name` | Chest radiography、CT head |
| 心内开单 | `cardiology_ordered` 的 subtype | ECG、Echo |
| 呼吸开单 | `respiratory_ordered` | 具体 subtype，不是泛 Lab |
| 高信号化验 | 冻结 itemid 名单 | 肌钙蛋白、乳酸、D-dimer、脂肪酶、BNP/NT-proBNP、血培养相关、ABG 组分等 |

高信号化验名单放 `config/mcq_visit_mining/investigation-catalog.yaml`，状态 `draft_unreviewed`。名单必须带 itemid，不准运行时按字符串模糊匹配现编。

**B. 附件 y（不进正式 accepted 主表）**

- 全部化验 `itemid` / `standard_test_name`（会看到电解质/血常规统治）
- POE `Lab` / `Imaging` 类别（`category_only`，只用于证明不能当答案）

Panel（BMP/CBC/LFT）**本轮不发明成分表**。检查选择主线的 `panel-definitions.yaml` 里 `clinical_panels: []` 仍空着。Visit 轨道也不准偷偷写「BMP = Na+K+Cl+…」除非另开临床审核。主分析靠「不把普适化学组分当 y」来避开基线陷阱，而不是靠未审核 panel。

同一窗口内同一 `outcome_id` 计一次（重复抽血不增加 n_y）。

### 6.6 条件组合

与题型 1 设计一致：

- 默认 `min_conditions=2`，`max_conditions=4`
- 至少 1 个 `symptom` / `physiologic_flag` / `absent`
- 至多 1 个年龄段、1 个性别
- `feature_id` 稳定排序
- Apriori：只有频繁子集才升阶
- 症状显示名与 y 名 casefold 相同则跳过（防「chest pain → Chest pain」这种假规则）

10,000 例上 `min_x_support=5` 偏松，会留下噪声。合同是：

| profile | 用途 | 门槛 |
|---|---|---|
| `strict`（默认主表） | 沿用 MCQ 8 门，见下 | 可进入 `conditional_rules.jsonl` |
| `exploratory` | 放宽 support / lift，**单独目录** | 不得与 strict 混文件 |

不得因为 strict 通过太少就在 10k 跑次中改门槛。要改门槛必须改 config 并换 output-dir。

### 6.7 统计量与 8 道门槛（strict）

对每个合法 `X → y`：

```text
n_total = 该 family 的事务数（通常=10,000，除非该 family 排除了无有效 y 的 visit）
n_x     = 含全部条件 X 的 visit 数
n_y     = 含 y 的 visit 数
n_xy    = 同时含 X 与 y 的 visit 数

conditional_probability = n_xy / n_x
smoothed_probability    = (n_xy + 1) / (n_x + 2)
baseline_probability    = (n_y + 1) / (n_total + 2)
lift                    = smoothed_probability / baseline_probability
```

另算：95% Wilson 下界、单侧 Fisher exact、Benjamini-Hochberg `fdr_q`（**按 family 内全部已测假设校正**）、bootstrap 第一名稳定性。

默认 score（只用于排序，不代替硬门槛）：

```text
score = wilson_lower × max(0, log2(lift)) × log(1 + n_xy) × bootstrap_stability
```

排序：`smoothed_probability` ↓ → `score` ↓ → `outcome_id` ↑。第一名 = target，第二名 = runner-up。

| 门槛 | 默认 | 淘汰什么 |
|---|---:|---|
| `min_x_support` | 5 | 条件太少 |
| `min_xy_support` | 4 | 共现太少 |
| `min_smoothed_probability` | 0.60 | 条件概率不够 |
| `min_lift` | 1.20 | 不比基线好（专门打 CBC/BMP 这类） |
| `min_wilson_lower` | 0.35 | 小样本区间太宽 |
| `max_fdr_q` | 0.05 | 多重检验后不显著 |
| `min_bootstrap_stability` | 0.80 | 第一名不稳定 |
| `min_probability_gap` / `min_score_ratio` | 0.15 / 1.25 | 与第二名分不开 |

bootstrap：`iterations=200`，`seed=20260820`，在 **X 所在 visit 集合**上重抽样，看 y 是否独占平滑概率第一名。

未过门槛 → `rejected`，记录稳定原因码（`low_x_support`、`low_lift`、`fdr_not_significant`、`ambiguous_probability_gap` 等）。只有 `status=accepted` 进入主规则文件。

无第二名、或该 X 下只有一个可用 y → 不能构成四选一，记 `insufficient_outcomes`，即使概率很高也不进 accepted 主表。

### 6.8 规则对象

accepted 与 rejected 同一 schema，用状态区分。对外 JSON **禁止**带 `hadm_id` 列表；共现清单若要调试，另写 gitignore 的 sidecar。

必要字段：`rule_id`、`family`、`condition_feature_ids`、`condition_display_names`、`target_outcome_id`、`target_outcome_name`、`n_*`、概率/lift/Wilson/Fisher/`fdr_q`/bootstrap/score、runner-up、gap、ratio、`status`、`rejection_reasons`、`window_id`、`catalog_sha256`、`profile`、`posthoc_flags[]`。

`rule_id = "rule:" + sha256(family | sorted feature_ids | target_outcome_id | window_id | profile)[:24]`

## 12. Key Decisions

1. **NER 停、时间线与挖掘先做。** 结构化主诉已 mapped≈96%，时钟已补齐；NER 解决的是叙事层，不是本轮统计层的阻塞。
2. **两个新站，不改 extract/standardize。** 时钟源与名称源本来就不在同一文件里，需要显式 join。
3. **不接入冠心病 protocol.yaml。** 并行五类题型底座，避免把 10k 随机 Visit 绑进冻结的 `conditional_order_choice`。
4. **题型① 用 4 小时首波窗口 + 选择代理，不用全住院、不用 POE Lab 类别。** 直接针对 V2 与 CBC/BMP 基线陷阱。
5. **主分析 y 不用未审核 panel，也不用全部 itemid。** 影像 exam、ECG/Echo、冻结的高信号化验。
6. **出院 ICD / 主服务 / 出院去向允许挖，但必须打后验标记，且不得当 gold。**
7. **10,000 例全量都挖，不再内划 formal split。** 样本已全部在 development 20% 池；本轮是 exploratory。
8. **统计公式自包含。** 抄 8 道门，不 import 失效表型，也不 import `investigation_selection.mining`。
