## 0. 执行结论

**可以，而且必须直接从 MIMIC 原始表抽取。**

第三版不以仓库里任何已生成住院归档、事件表、冠心病队列或旧 17 列 CSV 为输入。唯一合法输入是 `data/RawData/` 下的 MIMIC CSV.GZ。抽样键是原生 `(subject_id, hadm_id)`。目标是随机 10,000 条通过纳入漏斗的 Visit，按三份规范列出的全部字段抽出结果。**出院小结全文与标准章节是硬条件，不是可选项。**

正式交付是两份同构文件，**一行一次住院、一共 10,000 行**：

| 文件 | 形态 | 给谁看 |
|---|---|---|
| `visits.csv` | 表头 + 10,000 行；一列一个抽取字段 | 表格查看、筛选、导出入 Excel / pandas |
| `visits.json` | JSON 数组，恰好 10,000 个对象，键与 CSV 列同名同序 | 程序读取完整嵌套结构（检验时序、用药数组、DS 长文本） |

这两份里**只放抽取结果**，不放 `schema`、`lineage`、源表名、`note_id`、抽样 rank、哈希。溯源留在过程产物（`selection.jsonl`、`manifest.json`、内部 working 记录、验收计数），不写进最终行文件。

不允许作为本版输入的现有产物：

| 现有产物 | 为什么不能当输入 |
|---|---|
| `mimic_raw_archive` 的 10,000 例 `mimic_admission_raw` JSONL | 那是全表原样归档，不是 37 字段出题底座；且未做 DS/主诊断/年龄漏斗，抽样中出院小结覆盖仅 60.59% |
| 冠心病谱归档（108,833 住院）与其事件/聚合 | 按 ICD-9 410–414 / ICD-10 I20–I25 选队列，不是随机 Visit；且主线是检查选择，不是五类题型 visit 字段 |
| `event_pipeline` / `event_aggregation` | 事件化后字段名、时钟、payload 已变；出院小结被拆进 NER/事件，不再是规范要求的章节字段 |
| `data_pipeline/archived/parquet_to_jsonl` | 历史 Episode parquet 适配层，输入不是原始 CSV.GZ，且模块已归档 |
| `rwd_pipeline` 17 列 CSV | 字段不足（无 vitals/services/ED、Lab 无全时序、discharge_record 曾误用 Follow-up Instructions） |
| `data_pipeline/archived/phenotype/`、`versions/v2-llm-stem/` | 科学失效，禁止进入新抽取 |

本版只**借用**仓库已有的工程能力（`mimic_source_catalog` 的表路径与表头契约、SHA-256 确定性抽样算法、DS 标题正则），不读取那些模块写出的患者级文件。

```text
MIMIC CSV.GZ（data/RawData）
        │  Stage 0–3 纳入漏斗（年龄 / 主诊断 / 有效 DS+主诉）
        ▼
eligible Visit 全集（约数十万，以实测漏斗为准）
        │  Stage S  按 (subject_id, hadm_id) 确定性随机抽 10,000
        ▼
10,000 条抽样清单
        │  Stage 4–6 只对这 10,000 个 hadm_id 投影规范字段
        ▼
内部 working 记录（含溯源，不对外）
        │  Stage 7 结构验证 / DS 一致性 / 剥掉溯源后写出
        ▼
visits.csv + visits.json（10,000 行，只含抽取结果）
        │
        ▼
验收报告（docs/reports/，不含患者原文）
```

本版**不**进入题目生成、TF-IDF、Lift、clinical review 或 gold。抽完并通过结构验收后，数据状态仍是 `exploratory_unreviewed`。

## 2. 目标与非目标

### 2.1 目标

1. 从 MIMIC 原始表得到 **恰好 10,000** 条 Visit，每条对应唯一 `hadm_id`。
2. 每条 Visit 含三份文档要求的全部出题字段；出院小结必须有选定 DS 的 `text` 全文，以及可解析的 Chief Complaint。
3. **最终对外文件**是扁平行：`visits.csv` 与 `visits.json` 各 10,000 行，列/键 = 抽取结果，不含溯源。
4. 抽取过程仍按 MIMIC 表.列投影，并在过程产物里保留足以复现与核对的溯源；最终行文件不要求、也不展示溯源。
5. 抽取层忠实记录，**不做信息隔离**；隔离留给出题引擎。
6. 抽样、漏斗、解析、写出全部确定性可复现；源文件指纹绑进 manifest（过程文件）。

### 2.2 非目标

- 不抽取全库 ~30 万 eligible Visit。
- 不把 32 张表整行塞进 JSON（那是 `mimic_admission_raw`）。
- 不事件化、不归一化、不做 snapshot、不挖规则、不出题。
- 不按冠心病 / 表型 / 旧 V2 候选筛选。
- 不把本 10,000 行文件送进 `evaluation_pipeline` 当 formal gold。
- 最终 `visits.csv` / `visits.json` 不写源表名、`note_id`、抽样 rank、schema 块。
- 不翻译、不改写、不跨住院补全、不合并多份 DS。

### 2.3 成功标准（抽数完成的定义）

同时满足才算本版抽取完成：

1. `visits.csv` 表头 + 恰好 10,000 数据行；`visits.json` 为长度 10,000 的数组。两文件 `hadm_id` 集合相同、顺序相同。
2. 两文件列/键集合与顺序 = §8.2 冻结清单；无 `schema` / `lineage` / 源键列。
3. 9 个必需字段非空；`discharge_note_full` 非空；`chief_complaint` 非空且为全文子串。
4. 过程产物（`selection.jsonl`、`working/*.jsonl`、`manifest.json`）仍可把每一行映射回 `(subject_id, hadm_id, ds_note_id)`；最终两文件不出现这些过程字段（`subject_id`/`hadm_id` 作为结果主键保留）。
5. 换一台机器用同一 `data/RawData` 可复现字节级一致的 `visits.csv` 与 `visits.json`。
6. 验收报告不含患者原文，可入库 `docs/reports/`。

## 4. Visit 定义与 10,000 例抽样

### 4.1 Visit

- 一行 = 一次住院 = 一个 `hadm_id`。
- `hadm_id` 只来自 `admissions.csv.gz`，禁止从 discharge / diagnoses / ED 反推。
- `admissions` 中 `subject_id` 或 `hadm_id` 空、或 `hadm_id` 重复 → 全局终止。
- 同一 `subject_id` 可有多个 `hadm_id`；各 Visit 独立，禁止跨住院合并。
- `subject_id`、`hadm_id` 全程按字符串保存，保留源值和前导零，不转整数。

### 4.2 为什么必须「先漏斗、再随机」，不能「先随机 10k 再补字段」

现有开发集 10,000 例 raw 归档（未做 eligible）的模块覆盖：

| 模块 | 非空住院比例 |
|---|---:|
| Note（含出院小结） | 68.73% |
| `note.discharge` | 60.59% |
| ED | 37.93% |

字段规范把 `narrative.chief_complaint` 和主诊断设为**排除 Visit 级必需**。若先随机 10k 再筛，预期只剩约 4–6 千条能出题，无法凑满「含出院小结的 1 万例」。

因此抽样总体是 **eligible Visit**，不是全部 admissions。

### 4.3 纳入漏斗（Stage 0–3）

漏斗只读 4 张表：`admissions`、`patients`、`diagnoses_icd`+`d_icd_diagnoses`、`discharge`。通过之后才碰 labevents 等大表。

```text
N0  admissions 全部住院                         ~546,028
      排除：patients 关联失败 / 年龄<18 或无法算 / 性别不是 M|F
N1  人口统计通过
      排除：无恰好一条 seq_num=1 / icd 空 / version 不是 9|10 / 连不上字典
N2  诊断通过
      排除：无 note_type=DS / 全部候选无明确非空 Chief Complaint
N3  eligible Visit
      再限制：subject_bucket(subject_id) < development_percent（默认 20）
N3dev  开发患者池内的 eligible
      按 sha256("{subject_id}:{hadm_id}") 取最小的 10,000 个
S   本版样本
```

Stage 3 之后**不再因为非必需字段缺失而丢 Visit**。抽中的 10,000 条即使没有 triage、没有影像、没有处方，也保留；对应字段按 §10 写 null / `[]`。

漏斗每一步必须落盘计数：`candidate_count`、`excluded_stage1`、`excluded_stage2`、`excluded_stage3`、`eligible_count`、`eligible_development_count`、`sampled_count=10000`。`eligible_development_count < 10000` 时失败，不得从测试患者池借行、不得放宽主诉/年龄。

### 4.4 确定性随机（不是 `random.sample`）

与 `data_pipeline/mimic_raw_archive/selection.py` **同一算法**，但候选集换成 eligible，而不是「开发池内全部 admissions」。

```text
subject_bucket(subject_id)
  = int.from_bytes(sha256(subject_id_ascii)[:8], "big") % 100

开发池: subject_bucket < development_percent     # 默认 20，按患者切，不按住院切

score(subject_id, hadm_id)
  = sha256("{subject_id}:{hadm_id}").hexdigest()

sampled = nsmallest(10000, eligible_development, key=score)
selection_rank = 0 .. 9999  （按 score 升序）
```

性质：

- 无随机种子；同一份 `data/RawData` + 同一 `development_percent` → 同一份 10,000 清单。
- 同一患者的所有住院同池，避免日后若从本样本切 val/test 时发生患者泄漏。
- 默认不碰 `subject_bucket >= 20` 的患者，留给将来 formal split。配置写成 `sample_pool: development`。若显式改成 `all`，必须换输出目录并在 manifest 标明「已消耗全库患者」，本计划默认禁止。

### 4.5 抽样清单格式

### 5.4 investigations

一个对象，四键固定：`laboratory` / `radiology` / `cardiology` / `respiratory`。

**laboratory** ← `labevents` ⋈ `d_labitems`（`itemid`）

- 过滤：`hadm_id` 匹配且 `subject_id` 一致；`value` / `valuenum` / `comments` 至少一个非空。
- 按 `itemid` 聚合；`results` 按 `charttime` 升序，并列时 `storetime`、`labevent_id`。
- 元素：

```json
{
  "itemid": 50912,
  "label": "Creatinine",
  "fluid": "Blood",
  "category": "Chemistry",
  "results": [
    {
      "charttime": "2103-01-15T08:00:00",
      "value": "1.5",
      "valuenum": 1.5,
      "valueuom": "mg/dL",
      "ref_range_lower": 0.4,
      "ref_range_upper": 1.1,
      "flag": "abnormal",
      "comments": null
    }
  ]
}
```

`itemid` 在 JSON 中可保留数值（源列是整数）；`label`/`fluid`/`category` 来自 `d_labitems`。连不上字典的 itemid：该结果行丢弃并计入 `warnings.lab_itemid_unmapped`，不终止。

**radiology** ← `radiology` ⋈ `radiology_detail`

- 只保留 `note_type = 'RR'`。`AR` 不纳入。
- `exam_name` = detail 中 `field_name = 'exam_name'` 的 `field_value`。
- 同一 `exam_name` 只留 `charttime` 最早的一份。
- 元素：`{exam_name, charttime, text, details:[{field_name, field_value, field_ordinal}]}`。

**cardiology / respiratory** ← `poe` ⋈ `poe_detail`

- `transaction_type = 'New'` 且 `order_type IN ('Cardiology', 'Respiratory')`。
- 元素：`{order_subtype, ordertime, poe_detail:[{field_name, field_value}]}`。
- 去重键：`order_type + order_subtype + 排序后的 poe_detail 内容`；重复留最早 `ordertime`。
- 数组按 `ordertime` 升序。

映射文档题型①答案还写了 `poe.order_type IN ('Lab','Imaging')`。37 字段已改用 labevents / radiology 识别项目（P1：`poe.order_subtype` 几乎全空）。Lab/Imaging 医嘱另存：

```text
supplements.poe_lab_imaging[]
  = poe where transaction_type='New' AND order_type IN ('Lab','Imaging')
    + 对应 poe_detail
```

题型①正式答案来源仍是 `investigations`，不是这个补充数组。补充数组只供对照「医嘱层 vs 结果层」。

### 5.6 treatments

**medications** ← `prescriptions` 且 `drug_type = 'MAIN'`，`drug` 去空白非空。保留同一药物全部处方（剂量调整是治疗演变），按 `starttime` 升序。元素固定 9 键：

`drug, prod_strength, form_rx, dose_val_rx, dose_unit_rx, route, doses_per_24_hrs, starttime, stoptime`

`starttime` / `stoptime` 是处方有效区间（开立/停用），不是 eMAR 给药时刻。源列缺失写 JSON `null`。不读 `pharmacy` / `emar`。

已冻结的 `random10k_dev20/visits.json`（schema 3.1.0）发布时丢掉了这两个时间键；补齐产物另写 `data/derived/mcq_visit_extract/random10k_dev20_medtimes/`，不覆盖抽取、不中断 NER。

**procedures** ← `procedures_icd` ⋈ `d_icd_procedures`。`icd_code` 非空，`icd_version` 为 9 或 10，能连到非空 `long_title`。去重：相同 `(icd_code, icd_version)` 留最早 `chartdate`。排序：`chartdate` → `seq_num` → `icd_version` → `icd_code`。元素：

`procedure_name`（= `long_title`）, `icd_code`, `icd_version`（JSON number `9` 或 `10`）, `chartdate`（MIMIC 操作日；没有时刻）。

## 6. 出院小结抽取（本版最重要的规则）

出院小结是五类题干的文本主干，也是题型⑤答案来源。10,000 例必须每例都有选定 DS。

### 6.1 候选

```text
discharge.note_type = 'DS'
AND discharge.hadm_id = 当前 Visit
AND discharge.subject_id = admissions.subject_id
AND discharge.text 去空白后非空
```

`note_type = 'AD'` 一律丢弃，禁止用补充记录拼章节。

### 6.2 选定一份，全字段共用

1. 对每份候选独立解析章节。
2. 只保留 `Chief Complaint` 章节去空白后非空的候选。
3. 有效候选按以下键**降序**取最新一条：
   1. `note_seq`
   2. `charttime`（ISO 时间字符串可比较；空值排在非空之后，即更旧）
   3. `storetime`（空值排在非空之后）
   4. `note_id` 字符串降序
4. 该份 DS 同时供给 #15–#21、#33–#37 和 `supplements.discharge_*`。禁止「主诉取新 DS、HPI 取旧 DS」。

### 6.3 章节解析算法（抽取规范 §5.1）

已知顶层标题（大小写不敏感；行首可选空白；标题末可选英文冒号；必须整行匹配）：

```text
Chief Complaint
Major Surgical or Invasive Procedure
History of Present Illness
Past Medical History
Social History
Family History
Allergies
Physical Exam
Pertinent Results
Studies
Brief Hospital Course
Medications on Admission
Discharge Medications
Discharge Diagnosis
Discharge Condition
Discharge Instructions
Follow-up Instructions
Followup Instructions
Follow Up Instructions
```

算法：

1. `\r\n` / `\r` → `\n`。
2. 正则：`^\s*(<标题>)\s*:?\s*$`，`MULTILINE | IGNORECASE`。
3. 目标章节 = 标题行之后到下一个已知顶层标题之前。
4. 去掉章节首尾空白，**保留**内部换行、空行、顺序、`___` 去标识化。
5. 切出空串 → 该字段 JSON `null`（主诉空则该 DS 不能当候选）。
6. 全文 `narrative.discharge_note_full` = 选定 DS 的 `text` 原文（只做换行归一，不做章节裁剪）。

`Followup Instructions` / `Follow Up Instructions` 仅作为 Follow-up 的标题变体，内容写入同一 `supplements.followup_instructions_text`。

### 6.4 Follow-up Instructions 不可用

规范：该章节 98.3% 存在，但内容 100% 为 `___`。抽取时：

- 检测并写 `supplements.followup_instructions_unusable`。
- 记运行日志计数 `followup_unusable_count`，不终止。
- **禁止**把该章节当作 `disposition.discharge_record`。
- 题型⑤答案字段锁定为 `Discharge Instructions`。

### 6.5 一致性闸门（抽取后必跑）

对每一行：

1. `chief_complaint` 是 `discharge_note_full` 的子串（允许首尾空白差异，不允许改字）。
2. #16–#21、#33–#36 以及 `supplements.discharge_diagnosis_text` 若非 null，必须是全文子串。
3. 重新对 `discharge_note_full` 跑同一解析器，结果与已写字段逐字段相等。

任一失败 → 该次运行失败（fail-closed）。不允许「大部分通过就写出」。试点 100 例阶段可以把失败 Visit 打入 `pilot_failures.jsonl` 供改解析器；正式 10,000 例不允许失败行。

### 6.6 为什么不从 raw JSONL 里再切 DS

`mimic_admission_raw` 虽含 `mimic_iv_note.discharge[].text`，但：

- 现有 10k 样本 39.41% 根本没有 discharge 行；
- 冠心病归档不是随机样本；
- 从中间 JSON 再切等于依赖另一套聚合是否完整，违反「直接提取想要的数据名」。

本版 `discharge.csv.gz` 按 `hadm_id` 过滤后在内存/DuckDB 解析。只对 10,000 个 ID 做，文本量可控。

## 7. 管线阶段（实现顺序）

```text
P0  源校验
P1  Stage 0–3 漏斗 → eligible 清单
P2  Stage S 抽样 → selection.jsonl（锁 10,000 个 hadm_id）
P3  Stage 4  对 10k 解析 DS 章节
P4  Stage 5  对 10k 抽 investigations / diagnoses / treatments
P5  Stage 6  对 10k 抽 services / ED vitals / 去向 / 补充表
P6  Stage 7  组装 JSONL + 验证 + manifest + 验收报告
```

P3–P5 可并行，但同一 `hadm_id` 只在 P6 汇合。任何源表必须先按抽样 `hadm_id` 过滤再处理。

### 7.1 P0 源校验

1. 3.2 + 3.3 所列文件存在。
2. 表头 == `mimic_source_catalog.SOURCE_BY_KEY[key].header`。
3. 计算每个源文件 SHA-256，写入 manifest `source_fingerprints`。
4. 校验失败不建输出目录里的 visits 文件。

### 7.2 P1 漏斗（DuckDB 推荐实现）

用 DuckDB `read_csv_auto(..., header=true)` 读 CSV.GZ。ID 列按 VARCHAR 读，避免 `100012` 变 `100012.0`。

建议 SQL 骨架（实现时可拆临时表）：

```sql
-- Stage 0
CREATE TABLE admissions AS
SELECT TRIM(subject_id) AS subject_id, TRIM(hadm_id) AS hadm_id,
       admittime, admission_type, admission_location, discharge_location
FROM read_csv_auto('.../admissions.csv.gz', all_varchar=true);

-- Stage 1
CREATE TABLE n1 AS
SELECT a.*, p.gender, p.anchor_age, p.anchor_year,
       CAST(p.anchor_age AS INTEGER)
         + CAST(strftime('%Y', CAST(a.admittime AS TIMESTAMP)) AS INTEGER)
         - CAST(p.anchor_year AS INTEGER) AS age_at_encounter
FROM admissions a
JOIN patients p ON a.subject_id = p.subject_id
WHERE p.gender IN ('M','F')
  AND age_at_encounter >= 18;

-- Stage 2：恰好一条 seq_num=1 且能 join 字典
-- Stage 3：DS 候选在 SQL 侧只做 note_type/text 非空；
--          Chief Complaint 必须在 Python 解析后筛，因为标题在 text 里
```

Chief Complaint 无法纯 SQL 可靠判断。P1 应对 N2 的每个 hadm_id 拉 DS 文本、跑 §6.3，得到 N3。若 N2 过大，可：

1. SQL 先留下 `note_type='DS' AND length(trim(text))>0` 的 hadm_id；
2. 流式解析 DS，通过才写入 `eligible.jsonl`。

解析器必须与 P3 同一函数，避免漏斗用宽松规则、落盘用严格规则。

### 7.3 P2 抽样

读 `eligible.jsonl`，滤 `subject_bucket < 20`，`heapq.nsmallest(10000, ..., key=score)`，原子写 `selection.jsonl`。此后 P3–P5 的 SQL 一律：

```sql
JOIN selection s ON c.subject_id = s.subject_id AND c.hadm_id = s.hadm_id
```

`labevents` 全库极大，这是唯一可接受的扫描方式。禁止对全库 labevents 做 visit 级聚合。

### 7.4 P3–P5 投影

每张大表：DuckDB COPY 成「仅 10k hadm_id」的 parquet 或 Arrow 表，再在 Python 里按规范聚合。参考 `mimic_raw_archive` 的 staging，但**只保留 §3 列出的列**，不要 32 表全列。

建议分片：`shard_size=1000` → 10 个分片 working JSONL（含溯源），最后按 `selection_rank` 合并成内部 working 文件，再投影成正式 `visits.csv` / `visits.json`。分片失败可重跑单片，不得重抽 selection。

### 7.5 P6 写出（过程带溯源，交付剥掉溯源）

1. 先按 `selection_rank` 升序写出内部 `working/visits.working.jsonl`（每行含结果字段 + `lineage`，只给校验与复现用）。
2. 用 working 跑 DS 子串、必需字段、行数闸门。
3. 通过后投影为正式交付：每个对象只保留 §8.2 的结果键，**删除** `schema`、`lineage`、源键、抽样元数据。
4. 原子写 `visits.csv` 与 `visits.json`（先 `.partial`，`fsync` 后 `os.replace`），并写各自 sha256。
5. CSV 编码 `utf-8-sig`（Windows Excel 可识别 BOM），RFC 4180 引号，嵌入换行保留在单元格内。JSON 编码 UTF-8，无 BOM，数组紧凑写出。

### 7.6 断点续传（实现硬约束）

抽取会扫 `labevents` / `discharge` 等大表，正式 10,000 例和漏斗都可能跑数小时。代码必须按 `mimic_raw_archive` 同一套原则做成**可断点续跑**，而不是整次重来。

#### 原则

1. **身份绑定**：`manifest.json` 的 `identity` 由 `data_root`、源文件内容 SHA-256、`sample_size`、`shard_size`、`development_percent`、`sample_pool`、结果列清单组成。目录里已有 manifest 且 `identity_sha256` 不一致 → **拒绝续跑**（换输出目录）。一致才续跑。
2. **抽样锁定**：`selection.jsonl` 一旦原子写入，续跑只读、禁止重算、禁止换 10,000 个 `hadm_id`。漏斗未完成时不得写 selection。
3. **完成才算完成**：每个阶段/表/分片必须「内容 + sha256 + status=complete」三者对账。`.partial` 视为未完成，续跑时删除后重做。
4. **已完成分片损坏 → fail-closed**：manifest 记 complete 但文件缺失或哈希变了，终止，不静默重算（避免磁盘静默损坏被当成新结果）。
5. **粒度**：漏斗按 n1 / n2 / eligible 三份清单；源表 staging 按表；Visit 组装按 `shard_size`（默认 1000，正式 10 片）；交付文件是 cheap 投影，working 齐则可单独重写。
6. **原子落盘**：所有正式文件走 `*.partial` → `fsync` → `os.replace`。
7. **同一命令续跑**：不需要额外 `--resume` 开关。对同一 `output_dir` 再执行同一 CLI 即续跑。

#### 恢复矩阵

| 现场 | 动作 |
|---|---|
| 无 manifest | 新跑：P0 起 |
| manifest 身份不一致 | 终止，不混跑 |
| P0 源指纹已记且文件哈希仍一致 | 跳过重复说明，仍须能打开文件 |
| `n1.jsonl` complete 且哈希一致 | 跳过 Stage 1 |
| `n2.jsonl` complete 且哈希一致 | 跳过 Stage 2 |
| eligible 分片 complete | 跳过该 DS 解析片 |
| `eligible.jsonl` complete | 跳过整段漏斗 |
| `selection.jsonl` 存在 | **只读复用**；行数必须等于 `sample_size` |
| `staging/<key>.parquet` complete + integrity 一致 | 跳过该表 COPY |
| staging 记 complete 但文件没了 / 哈希变了 | 终止 |
| `working/part-NNNNN.jsonl` complete + sha256 一致 | 跳过该 Visit 分片 |
| 分片 `.partial` 残留 | 删除后重做该片 |
| 全部分片 complete，`visits.csv`/`visits.json` 缺或哈希不符 | **只从 working 重投影**，不重扫 MIMIC |
| 交付文件齐且哈希一致 | 整次运行视为完成，立即返回 |

#### 禁止

- 续跑时用新随机数或重新 `nsmallest` 覆盖 selection。
- 把未 complete 的分片拼进 `visits.csv`。
- 身份变了还往旧目录追加。
- 用「删了交付文件就当没抽过」去重做 staging（交付缺了只重建投影）。

模块入口必须用单测覆盖：第二次 `run()` 复用已完成分片且 sha256 不变；删掉交付文件后只重建 csv/json；改 `sample_size` 被拒绝。

### 8.5 CSV 读写约定

- 方言：`csv.excel`，分隔符 `,`，引号 `"`，引号转义为 `""`。
- 含逗号、换行、引号的单元格必须加引号。DS 章节保留内部换行。
- 标量缺失：CSV 写空单元格，不要写字符串 `"null"` 或 `"None"`。
- 集合缺失：写 `[]` 或 investigations 的四键空对象，与 JSON 一致。
- `subject_id` / `hadm_id` / `primary_icd_code` 必须当文本写出（避免 Excel 吃掉前导零）。CSV 中这两列建议写成 `="10000032"` **不采用**（那是 Excel 公式，会破坏 pandas）。保持纯文本；用 `utf-8-sig` + pandas `dtype=str` 读取。
- **Excel 限制**：单个单元格上限 32,767 字符。`discharge_note_full` 与 `investigations` 经常超过。用 Excel 打开 CSV 可能截断；**完整无损内容以 `visits.json` 为准**。用 Python：

```python
import pandas as pd
df = pd.read_csv("visits.csv", encoding="utf-8-sig", dtype=str, keep_default_na=False)
assert len(df) == 10000
```

长文本被 Excel 截断不算抽取失败；`visits.json` 与 pandas 读 CSV（不经 Excel 另存）必须完整。

## 15. 逐题型：抽完 10k 后各字段是否够用

这是抽取完整性核对，不是出题计划。

### 题型① 检查检验选择

| 角色 | 字段 | 10k 样本预期 |
|---|---|---|
| 题干 | age, sex, chief_complaint, HPI, PMH, medications_on_admission | 前三项 100%；HPI/PMH/用药章节规范存在率 ~100%/100%/~100% |
| 条件 | vitals, admission_type, social_history, allergies | vitals ~47%；其余章节高 |
| 答案 | `investigations` | Lab 覆盖高；无检查的 Visit 答案数组为空，出题层应跳过而非在抽取层丢行 |

### 题型② 临床诊断

答案 `diagnoses.primary` + `other` 在漏斗后 100% 有主诊断。题干需要至少一项关键检查结果：出题层过滤 `investigations.laboratory|radiology` 非空的子集。

### 题型③ 治疗处置

答案 `treatments.medications|procedures`。无 MAIN 处方且无操作的 Visit 不能出治疗题，抽取仍保留。

### 题型④ 转诊科室

答案 `primary_service` + `discharge_location`。`primary_service` 在 raw 10k EDA 中 services 覆盖 100%；本版 eligible 预期同样高。无 ED 不影响（`ed_disposition` 为条件）。

### 题型⑤ 离院指导

答案 `disposition.discharge_record`（Discharge Instructions，规范存在率 99.2%）。Follow-up 不可用已在 §6.4 处理。`brief_hospital_course` / `discharge_medications` / `discharge_condition` 作条件。

## 17. 风险与预决策

| 风险 | 预决策 |
|---|---|
| 开发池 eligible 不足 10,000 | 停止。先核对 DS 解析是否过严（例如标题行带多余符号）。仍不足才允许把 `development_percent` 提到 30，必须换输出目录并写进 manifest。禁止用测试桶补齐 |
| DS 标题在部分医院模板不换行 | 试点 100 的人工对照专门抓这个问题；只允许扩展「整行标题」正则的空白/冒号，不允许用 LLM 切章 |
| labevents 对 10k JOIN 仍很慢 | 先 staging 成 parquet 再聚合；机器内存不够就降 `duckdb-memory-limit` 并减线程，不改字段 |
| 同一 subject 抽到多次住院 | 允许。Visit 主键是 hadm_id。报告里给出 unique_subject_count |
| 有人想「借」现成 10k raw 再切字段以省时间 | **拒绝**。覆盖率不够，且违反本版输入契约 |
| 与检查选择 1,000 例 overlap | 不刻意排除也不刻意对齐；两套抽样独立。若需无 overlap，另开计划 |
| 出院小结去标识化 `___` 过多导致主诉无意义 | 主诉非空即可入漏斗；出题层再筛「主诉不只是 `___`」。抽取层不二次猜测 |
| Excel 打开 CSV 截断超长单元格 | 预期行为。完整内容以 `visits.json` 和 pandas 读取的 CSV 为准，不以 Excel 另存为准 |
| 交付文件误带 lineage | 投影用 45 键白名单；单测断言交付文件不含 `ds_note_id` |
