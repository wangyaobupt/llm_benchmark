## 1. 一句话定位

基于 **MIMIC-IV v3.1** 真实世界数据构建香港 RWD 临床基准，最终目标是生成**五类英文 A–D 单选临床 MCQ**，用于评估 LLM 在真实诊疗流程中的临床判断能力。

## 2. 临床流程与五类题型

题目围绕统一临床流程组织：`患者信息 → 检查检验 → 临床诊断 → 治疗处置 → 转诊科室 → 离院指导`。五类题型逐一对应决策点。

| # | 题型 | 一句话定位 |
|---:|---|---|
| 1 | Clinical investigation selection（检查检验选择） | 预测在给定患者特征下真实世界中最可能被选择的检查项，即 `P(检查项 | 特征)` 排名第一 |
| 2 | Clinical diagnosis（临床诊断） | 根据患者信息与关键检查检验结果作出本次就诊的临床诊断 |
| 3 | Treatment and management（治疗与处置） | 基于已确定诊断选择正确的治疗处置方案 |
| 4 | Referral and specialty selection（转诊与科室） | 根据诊断或病情判断应转诊的服务方向或科室 |
| 5 | Discharge advice and follow-up（离院指导） | 针对治疗后病情稳定、准备离院的患者给出随访与生活指导 |

题型 1 目前已有完整设计文档（Stage 0–10），题型 2–5 仅在 `mcq_generation/question_types.md` 中有题型规范，尚未出题设计。

## 7. 数据契约：字段级映射表

> 以下字段映射描述**旧版 17 列 CSV 路线**。新 JSONL 主线使用 37 字段结构，字段规范详见 `data/出题数据抽取字段规范.md`（本地文件，`.gitignore` 排除）。

### 7.1 抽取产物（17 列）— 原始字段

| # | 字段 | 类型 | 权威来源 | 必需性 | 缺失表示 |
|---:|---|---|---|---|---|
| 1 | `subject_id` | str | `admissions.subject_id` | 必需 | 缺失→排除 Visit |
| 2 | `hadm_id` | str | `admissions.hadm_id` | 必需 | 缺失→排除 Visit |
| 3 | `age_at_encounter` | int | `patients.anchor_age/year` + `admissions.admittime` | 必需 | 无法计算→排除 |
| 4 | `sex` | M/F | `patients.gender` | 必需 | 无效→排除 |
| 5 | `chief_complaint` | str | DS 的 Chief Complaint 章节 | 必需 | 缺失→排除 |
| 6 | `history_of_present_illness` | str | DS 的 HPI 章节 | 非必需 | 空单元格 |
| 7 | `past_medical_history` | str | DS 的 Past Medical History 章节 | 非必需 | 空单元格 |
| 8 | `medications_on_admission` | str | DS 的 Meds on Admission 章节 | 非必需 | 空单元格 |
| 9 | `investigation_orders` | JSON 对象数组 | `poe` + `poe_detail` | 非必需 | `[]` |

Visit 纳入条件：年龄≥18、性别有效、有有效主诊断、有含 Chief Complaint 的 DS 出院小结，任一不满足则整 Visit 排除。

### 7.2 清洗产物（17 列）— 仅改 4 个字段

清洗保持 17 列、行数、顺序、ID 逐行一致。仅以下 4 个字段由自由文本变为 LLM 抽取的 JSON 字符串数组：

| # | 字段 | 清洗前 | 清洗后 | 处理 |
|---:|---|---|---|---|
| 5 | `chief_complaint` | 自由文本 | `["entity1","entity2"]` | LLM 抽主诉实体 |
| 6 | `history_of_present_illness` | 自由文本 | JSON 数组 | LLM 抽病程实体 |
| 7 | `past_medical_history` | 自由文本 | JSON 数组 | LLM 抽既往临床实体 |
| 8 | `medications_on_admission` | 自由文本 | JSON 数组 | LLM 抽入院药物名 |

清洗规则要点：调 LLM 前删除 `___` 和 `[**...**]` 去标识化占位符；保留原文医学表达，不展开缩写/不翻译/不合并同义词；否定实体不输出；仅表面重复去重。其余 13 列逐值复制不动。

### 7.3 标准化产物（15 列）— 字段流转

从 17 列合并/标准化为 15 列：

| 标准化字段 | 来源 | 处理 |
|---|---|---|
| `subject_id`、`hadm_id`、`age_at_encounter`、`sex` | 同名复制 | 逐值复制 |
| `chief_complaint`、`history_of_present_illness`、`past_medical_history`、`medications_on_admission` | 清洗 4 字段 | 字段专属映射标准化为标准名称，JSON 数组，确定性别名优先 |
| `investigation_orders` | 清洗同名字段 | **逐字节原样复制**，不做标准化 |
| `investigation_reports` | 清洗同名字段 | 实验室/放射结果标准化（单位等价、检验结构固定） |
| `primary_diagnosis` | `primary_diagnosis_name` + ICD code + version | 映射为标准名称标量（合并 3 列为 1 列） |
| `other_diagnoses` | 清洗同名字段 | 映射为标准名称 JSON 数组 |
| `medication_prescriptions` | 清洗同名字段 | 成分映射 + 剂量解析（single/range/text/missing）+ 结构固定 |
| `procedures` | 清洗同名字段 | 映射为标准名称 JSON 数组 |
| `discharge_record` | 清洗同名字段 | 逐值复制，不改写 |

**3 列变化**：`primary_icd_code` + `primary_diagnosis_name` + `primary_icd_version` 合并为 `primary_diagnosis` 一列。

## 8. 关键技术约定

- **LLM 统一用 DeepSeek**：模型 `deepseek-v4-flash`，Base URL `https://api.deepseek.com`，Key 走环境变量。
- **去标识化**：MIMIC 的 `[**...**]` 和 `___` 占位符在调 LLM 前删除；LLM 返回含占位符则判无效并重试。
- **JSON 紧凑 UTF-8**：不写 `NaN`/`Infinity`/字符串空值；属性缺失用 JSON `null`。
- **原子替换**：标准化输出先写临时文件，全部校验通过后才替换目标文件，避免半写入。
- **Checkpoint 断点续跑**：清洗按行×字段哈希做 checkpoint，中断后可复用已完成结果。
- **双阶段 LLM 映射 + manifest**：标准化先 `build-mappings`（候选生成 + 独立等价复核），再 `transform`（纯查表，映射缺项即终止，不运行时调 LLM）；manifest 记录模型/规则版本/映射 SHA-256，换模型必须重建映射并升版本。
- **失败关闭**：统计证据不足、映射缺项、校验失败时一律终止，不兜底。
