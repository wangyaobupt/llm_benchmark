## 概览

面向患者单次就诊全流程的临床决策评测集（patient-journey benchmark），评估模型能否在不同临床决策节点，仅依据“当时已经发生且已经可用”的信息作出合理决策。

当前以 MIMIC-IV v3.1、MIMIC-IV-ED 2.2 和 MIMIC-IV-Note 2.2 开发、验证并冻结方法学；后续在香港真实世界资料上做本地适配和外部验证。MIMIC 上冻住的字段映射、统计阈值、行为 gold 和流程，不会直接搬到香港数据。

最终产物计划是五类英文 A–D 单选临床决策题，用于评估 LLM 在一次诊疗流程中的五项能力：

1. **检查检验选择**（当前唯一正式重建中的任务）
2. **临床诊断**
3. **治疗与处置**
4. **转诊与科室选择**
5. **离院指导与随访** → **MIMIC 没有独立随访 gold**，这一维目前只有骨架，不能出正式题

两类 gold 不混用：行为一致性任务回答“真实临床中最可能发生什么”；规范性任务回答“依据临床证据最应该做什么”。前瞻性题目只允许使用决策时点已经发生且已经可用的信息；出院 ICD、行政终点、后验文书不能进题干。

本轮检查选择的科学合同已经写入 `config/investigation-selection/protocol.yaml`：

```yaml
protocol_status: frozen
decision_semantics: conditional_order_choice
# 含义：已知该时点发生了一次合格检查开单，预测同一冻结定义下观察到的检查候选。
# 不允许写成“预测医生下一步会不会开检查”。
```

旧 V2（phenotype 特征 + 规则挖掘 + 134 道候选）已整链失效，不能送审、不能发布、不能当新统计基线。

### 数据清洗

#### ① mimic_raw_archive：按住院抽出 32 张表，一行一个 `hadm_id`

**做什么。** 不改写 MIMIC 原值。把 39 个锁定 CSV.GZ 按原生键连到 `{subject_id, hadm_id}`，输出一次住院一行的嵌套 JSONL。分模块内嵌是为了可追溯：每一张源表仍是独立数组，字段顺序等于官方表头。代价是不直观，临床可读性要等到 ②。

**处理逻辑。**

1. 校验 39 个文件是否存在，表头是否与锁定目录逐列一致。漂移直接失败。
2. 先冻结住院清单（冠心病选择或随机抽样），`selection_rank` 必须从 0 连续、无重复 `hadm_id`。
3. 把源文件指纹、schema、抽样清单打成 `identity_sha256`。已有 manifest 指纹对不上就拒绝续跑，避免混批。
4. DuckDB 按分片抽取；父子表（如 `poe_detail` 跟 `poe`）用原生键挂上，不按时间猜。
5. 组装时所有值保持字符串原值，不派生字段。

**关键代码。** 运行入口先校验源文件，再创建或续跑清单：

```python
# data_pipeline/mimic_raw_archive/extractor.py
```

#### ② clean_clinical_archive：追加解码，并重建 POE 时间线

**做什么。** 两件事，都不改原始字段：

1. **Decode**：用五份官方字典给源行追加 `*_decoded`。
2. **POE 时间线**：把 `poe` + `poe_detail` + `prescriptions` + `pharmacy` 折成按 `ordertime` 排序的生命周期事件，写入派生表 `hosp.poe_timeline`。

做完后做可逆性自检：剥掉解码字段和 `poe_timeline`，必须逐字段等于输入。改了原值就失败。

**处理逻辑 —— Decode。**

规则表写死了哪张表用哪本字典、用哪些键、写到哪个字段。查不到代码直接抛错，不猜：

```python
# data_pipeline/clean_clinical_archive/decoder.py
DECODE_RULES = (
    DecodeRule("mimic_iv_hosp", "labevents", "d_labitems", ("itemid",), "itemid_decoded"),
    DecodeRule("mimic_iv_hosp", "diagnoses_icd", "d_icd_diagnoses",
               ("icd_code", "icd_version"), "icd_decoded"),
    DecodeRule("mimic_iv_icu", "procedureevents", "d_items", ("itemid",), "itemid_decoded"),
    # …
)

def decode_record(record, dictionaries, record_index, decoded_counts, null_key_counts):
    for rule in DECODE_RULES:
        for row_index, row in enumerate(_rows_for_rule(record, rule, record_index)):
            if rule.decoded_field in row:
                raise DecodeError("already contains decoded field")
            key = _source_key(row, rule, record_index, row_index)
            if key is None:
                null_key_counts[rule.path] += 1
                continue
            entry = dictionaries[rule.dictionary].get(key)
            if entry is None:
                raise DecodeError(f"unresolved code … in {rule.dictionary}")
            row[rule.decoded_field] = {"source_dictionary": rule.dictionary, **entry}
```

所以 `itemid=50801` 变成可读检验项目：

```json
{
  "itemid": "50801",
  "itemid_decoded": {
    "source_dictionary": "d_labitems",
    "itemid": "50801",
    "label": "Glucose",
    "fluid": "Blood",
    "category": "Chemistry"
  }
}
```

**处理逻辑 —— POE 时间线。**

`transaction_type` 只认官方集合。`New/Change/D/C` 映射成 create/change/discontinue；`Co/H/T` 等不发明临床动作。链的根不是当前 `poe_id`，而是沿 `discontinue_of_poe_id` 往回走到根：

```python
# data_pipeline/clean_clinical_archive/poe/parser.py
ACTION_LABELS = {
    "New": ("create", "新开"),
    "Change": ("change", "变更"),
    "D/C": ("discontinue", "停止"),
}

def parse_admission(record):
    hosp = record["mimic_iv_hosp"]
    orders = hosp["poe"]
    # 按 poe_id 挂 detail / prescription / pharmacy
    # 再按 ordertime 排序，逐条生成 timeline event
    root_id, chain_position, cycle, chain_complete = _root_and_position(order, by_id)
    event = {
        "schema": {"name": "mimic-poe-timeline-event", "version": "2.0.0"},
        "event_time": order["ordertime"],
        "poe_id": poe_id,
        "action": action,                    # create / change / discontinue
        "clinical_category": {
            "raw": current.get("order_type"),
            "subtype_raw": current.get("order_subtype"),
        },
        "content_specificity": content_specificity,  # entity_specific / subtype_only / category_only
        "incremental_information": increment,        # 相对前序订单新增了什么
        "relations": {
            "chain_root_poe_id": root_id,            # 生命周期 ID，不是单行 poe_id
            "chain_position": chain_position,
            "chain_complete": chain_complete,
        },
        "provenance": {"current": {"poe": order, "poe_detail": …}},
    }
```

Lab 医嘱在 MIMIC POE 里通常只有 `order_type=Lab` 和 `order_subtype=CBC`，没有具体项目名。时间线会标 `content_specificity: subtype_only` 或 `category_only`，后面检查选择必须把 Lab POE 当成 `generic_lab_order`，具体化验走 `labevents` 结果代理。

#### ③ event_pipeline：嵌套源行 → 一行一事件，再做确定性归一化

**做什么。** 把临床可读 JSONL 拆成 `clinical_event/1.2.0` 事件表。清洗阶段只负责身份、时间、事件类型、血缘；归一化阶段只填 8 个术语/单位字段，其余列逐值不变。清洗审计不 import 生产 transformer，而是独立重算期望值再比对。

33 张登记表是封闭世界：21 张事实源、6 张支持源、6 张上下文源。未登记的表直接拒绝。

一条命令走完全部门禁：

```powershell
python -m data_pipeline.event_pipeline run DATA-clinical-readable.jsonl `
  --raw-source-jsonl DATA-raw.jsonl `
  --output-dir data\BATCH\event_pipeline_output
```

工作流是：清洗 → 独立审计清洗 → 归一化 → 独立审计归一化 → 换 batch size 复跑并比对 SHA-256 → 原子发布 `workflow_manifest.json`。任何一关失败，正式目录不出现。

##### 3.1 事件化（cleaning）

先按源表目录把每个数组元素做成 `SourceRow`，再用原生键生成稳定 `source_row_id`：

```python
# data_pipeline/event_pipeline/event_cleaning/ids.py
def build_source_row_id(spec, row, *, duplicate_occurrence_ordinal=0):
    key_values = [f"{field}={row[field]}" for field in spec.native_key_fields]
    identity = "|".join(key_values)
    return f"src:{_digest(spec.module, spec.table, identity)}"

def build_event_id(source_row_id, component):
    return f"evt:{_digest(source_row_id, component)}"   # 一行源数据可裂成多条事件
```

同一源行可以产出多条事件。例如 ED triage 一行会裂成主诉、生命体征、acuity。`component` 不同，`event_id` 就不同。

统一事件壳在 `_event()`：清洗阶段 `concept_id` / `preferred_name` / 归一化字段一律留空，避免清洗和归一化职责混在一起。

```python
# data_pipeline/event_pipeline/event_cleaning/transformers/common.py
def _event(source, component, event_kind, *, times=None, …):
    event_id = build_event_id(source.source_row_id, component)
    return {
        "schema_version": "1.2.0",
        "event_id": event_id,
        "source_row_id": source.source_row_id,
        "event_kind": event_kind,
        "assertion": "present",
        **resolved_times(…),
        "time_policy_id": source.spec.time_policy,
        "evidence_phase": "source_event",   # ICD 诊断会标 post_hoc
        "source_concept_id": concept_id,    # 源编码，只标注
        "concept_id": None,                 # 归一化阶段才填
        "raw_row_ref": source.raw_row_ref,  # 文件#行号/模块.表[下标]
        "quality_flags": …,
    }
```

**时间逻辑。** `event_time` 是事实发生时间，`available_time` 是泄漏安全的可见时间。检验用 `charttime`（抽血）和 `storetime`（结果入库）。如果 `storetime < charttime`，不是改源值，而是把有效 `available_time` clamp 到 `event_time` 并打旗：

```python
# data_pipeline/event_pipeline/event_cleaning/time_resolver.py
def resolved_times(*, event_time=None, available_time=None, recorded_time=None, completion_time=None):
    event = iso_time(event_time)
    source_available = iso_time(available_time)
    available = source_available
    if source_available and event and source_available < event:
        quality_flags.append("AVAILABLE_BEFORE_EVENT_TIME")
    if event and available and available < event:
        available = event
        quality_flags.append("AVAILABLE_TIME_CLAMPED_TO_EVENT_TIME")
    # 两头都缺 → unresolved；只有一头 → partially_resolved
```

##### 3.2 归一化（normalization）

只填术语和单位。规则冻结在 `event-terminology/1.1.0`。不由 LLM 猜映射。

```python
# data_pipeline/event_pipeline/event_normalization/terminology.py
def resolve_term(entity_type, source_concept_id, source_label):
    if source_concept_id and _source_code_is_usable(source_concept_id):
        return {"concept_id": source_concept_id, "normalization_status": "mapped",
                "mapping_rule": "source-code"}
    if source_concept_id:
        return {"concept_id": None, "normalization_status": "unresolved",
                "mapping_rule": "invalid-source-code"}   # 全 0 NDC 走这里
    reviewed = REVIEWED_TEXT_MAPPINGS.get((entity_type, normalized_text(source_label)))
    if reviewed:
        return {"concept_id": reviewed[0], "normalization_status": "mapped"}
    return {"concept_id": None, "normalization_status": "unresolved"}
```

##### 5.5 时点查询：当时开了什么，当时已经能看见什么

```python
# query.py
def visibility_decision(event, *, index_time, query_start):
    if event_time >= index_time:
        return False, "EVENT_NOT_PREINDEX"     # 等于 index 也不放行
    if available_time is None:
        return False, "AVAILABLE_TIME_UNKNOWN"
    if available_time > index_time:
        return False, "NOT_YET_AVAILABLE"
    if phase == "post_hoc":
        return False, "POST_HOC"
    recency_time, _ = recency_clock(event)
    if query_start is not None and recency_time < query_start:
        return False, "RECENCY_WINDOW_EXPIRED"
    return True, "INCLUDED"
```
