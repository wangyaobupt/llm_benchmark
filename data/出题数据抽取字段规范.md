# 出题数据抽取字段规范

> **生成日期**: 2026-08-07
> **数据版本**: MIMIC-IV v3.1 (hosp/icu) + MIMIC-IV-ED v2.2 (ed) + MIMIC-IV-Note v2.2 (note)
> **设计依据**: `mcq_generation/question_types.md`（五类题型字段规范）、`data/出题全流程字段需求映射.md`（临床数据类别→MIMIC 映射）、MIMIC 原始数据实际列结构与值分布验证
> **前置文档**: `rwd_pipeline/rwd_benchmark_extraction_spec.md`（现有 17 字段抽取实现规范）

---

## 一、文档定位

本文档定义从 MIMIC-IV 抽取的 **visit 级 CSV 表格**的完整字段结构。每行是一个住院（`hadm_id`），每列是一个字段。该表格是五类临床 MCQ 题型的统一数据底座。

以现有 30 列提案为基础，纳入五轮自评估全部修复和数据验证发现，最终为 **35 列**。

---

## 二、设计原则

### 2.1 信息隔离

每道题的**题干信息字段**和**答案来源字段**必须严格分离。答案来源字段不得泄漏进题干。

### 2.2 DS 章节独立提取

出院小结（DS）的每个标准章节提取为独立字段，而非拼接为单一文本。数据验证确认 14 个标准标题在 DS note 中稳定出现（20 条采样样本，100% 覆盖）：

`Chief Complaint` / `History of Present Illness` / `Past Medical History` / `Social History` / `Family History` / `Physical Exam` / `Pertinent Results` / `Brief Hospital Course` / `Medications on Admission` / `Discharge Medications` / `Discharge Diagnosis` / `Discharge Condition` / `Discharge Instructions` / `Follow-up Instructions`

### 2.3 结构化优先

能从结构化表（admissions / diagnoses_icd / prescriptions / poe / services / triage）直接获取的数据，不从自由文本推断。

### 2.4 生命体征独立成列

体温、心率、呼吸、血压等生命体征拆分为独立列（#6-#13），而非打包为 JSON 对象。原因：出题时常需单独引用某项生命体征（如"血压 90/60"），独立列便于直接筛选异常值和构造条件题干。

## 四、逐字段抽取规则

以下详述 30 列提案中未明确的字段（生命体征、服务/去向）及全部新增字段。#1-#4、#15-#18、#22-#27 的规则见 `rwd_benchmark_extraction_spec.md`，此处不重复。

### 4.1 `admission_type`（新增 #5）

- **语义**: 入院途径类型，反映就诊紧急程度。
- **来源**: `dataset/hosp/admissions.csv` 的 `admission_type` 列。
- **关联**: 与 `hadm_id` 同行。
- **必需性**: 必需。值为空时排除 Visit。
- **保存格式**: str，保留源值，不去重、不合并、不标准化。
- **实际值分布**（全库 546,028 条 admissions）:

| 值 | 含义 | 计数 |
|---|---|---|
| `EW EMER.` | 急诊急诊入院 | 177,459 |
| `EU OBSERVATION` | 急诊留观 | 119,456 |
| `OBSERVATION ADMIT` | 留观后入院 | 84,437 |
| `URGENT` | 紧急入院 | 54,929 |
| `SURGICAL SAME DAY ADMISSION` | 日间手术入院 | 42,898 |
| `DIRECT OBSERVATION` | 直接留观 | 24,551 |
| `DIRECT EMER.` | 直接急诊 | 21,973 |
| `ELECTIVE` | 择期入院 | 13,130 |
| `AMBULATORY OBSERVATION` | 门诊留观 | 7,195 |

- **出题用途**: 题型① 判断检查优先级；题型④ 判断服务层级（急诊 vs 择期 vs 门诊）。

### 4.2 生命体征组（#6-#14）

#### 来源策略

首选 `triage` 表（急诊分诊首次测量），通过 `edstays.hadm_id` 关联当前 Visit，再经 `edstays.stay_id` 连接 `triage.stay_id`。

**ED 覆盖率**（数据验证）: 全库 69.5% 的住院有 `admissions.edregtime`（经过急诊）；37.1% 在 `edstays` 有 `hadm_id` 关联。无 triage 数据时 #6-#13 均为空单元格。

`vital_source`（#14）标记实际来源：

| vital_source 值 | 含义 |
|---|---|
| `triage` | 来自 triage 表（首选） |
| `chartevents` | 来自 ICU 床旁 chartevents（备选，当前版本未实现） |
| （空） | 无任何生命体征数据 |

#### 逐字段说明

| # | 列名 | triage 列 | 单位/含义 | 保存类型 |
|--:|---|---|---|---|
| 6 | `temperature` | `temperature` | 华氏度（出题时按需转 °C） | float/空 |
| 7 | `heartrate` | `heartrate` | bpm | float/空 |
| 8 | `resprate` | `resprate` | 次/分 | float/空 |
| 9 | `o2sat` | `o2sat` | % | float/空 |
| 10 | `sbp` | `sbp` | mmHg | float/空 |
| 11 | `dbp` | `dbp` | mmHg | float/空 |
| 12 | `acuity` | `acuity` | ESI 1-5（越小越紧急） | int/空 |
| 13 | `rhythm` | `vitalsign.rhythm` | 心律文本描述（如 "Sinus Rhythm"） | str/空 |

**rhythm 补充**: `rhythm` 不在 `triage` 表中，而在 `vitalsign` 表。取该 Visit 急诊期间（`vitalsign.stay_id` 关联 `edstays.stay_id`）的首次非空值。

**缺失规则**: 无 ED 关联或对应记录为空时，#6-#13 写空单元格，#14 写空字符串。

### 4.3 `physical_exam`（新增 #19）

- **语义**: DS 出院小结中记录的体格检查发现。
- **来源**: 选定 DS 的 `text` → `Physical Exam` 章节。DS 选择规则同现有规范（按 note_seq/charttime/storetime 降序选最新含 Chief Complaint 的 DS）。
- **章节识别**: 大小写不敏感的顶层标题匹配，允许标题末尾带英文冒号。
- **内容处理**: 去除首尾空白，保留内部原文、顺序、换行和 `___` 去标识化标记。
- **保存格式**: str。缺失时写空单元格。
- **出题用途**: 题型②③④ 条件题干信息。

### 4.4 `investigation_orders`（修正 #20）

#### 修正内容

| 修正点 | 原规则 | 新规则 |
|---|---|---|
| order_type 过滤 | `IN ('Lab', 'Imaging')` | `IN ('Lab', 'Radiology', 'Cardiology', 'Respiratory')` |

#### 修正依据（poe.csv 数据验证）

| 发现 | 说明 |
|---|---|
| `Imaging` 不存在 | poe 表中影像检查的 order_type 实际值为 `Radiology`，原过滤条件 `Imaging` 会丢失全部影像检查 |
| `Cardiology` 遗漏 | 心电图、超声心动图等心脏检查，题型① 示例题标准答案"十二导联心电图"属于此类 |
| `Respiratory` 遗漏 | 血气分析、肺功能检查等，题型① 需覆盖 |

#### Lab order_subtype 问题

数据验证发现 Lab 医嘱的 `order_subtype` 在采样中几乎全空。具体检验项目名称需从两条路径获取：

1. `labevents.itemid` + `d_labitems.label`（检验结果关联项目名称）
2. `poe_detail.field_name/field_value`（医嘱明细中的项目描述）

出题时需从 order_type + order_subtype + poe_detail 组合推导具体检查名称（如 "CT Head" = Radiology + CT + Body Part:Head）。

#### 保存格式

不变。JSON 对象数组，每个对象固定属性 `order_type`、`order_subtype`、`poe_detail`。其余去重、排序规则延续 `rwd_benchmark_extraction_spec.md` §5.9。

### 4.5 `primary_service`（#28）

- **语义**: 当前住院最终负责的医疗服务团队。
- **来源**: `dataset/hosp/services.csv`。
- **关联**: `hadm_id` 等于当前 Visit，`subject_id` 与 `admissions.subject_id` 一致。
- **选择规则**: 按 `transfertime` 升序取最后一条记录的 `curr_service`（即最终科室）。
- **保存格式**: str。缺失时写空单元格。
- **科室代码**（全库分布，计数前 10）:

| 代码 | 科室 | 计数 | | 代码 | 科室 | 计数 |
|---|---|---|---|---|---|---|
| MED | 内科 | 286,528 | | ORTHO | 骨科 | 26,991 |
| CMED | 心内科 | 54,452 | | NMED | 神经内科 | 26,709 |
| SURG | 普外科 | 51,640 | | OBS | 产科 | 24,923 |
| OMED | 肿瘤内科 | 33,549 | | NSURG | 神经外科 | 16,795 |

完整科室代码见 `data/出题全流程字段需求映射.md` §3.13。

- **出题用途**: 题型④ 答案来源。

### 4.6 `admission_location`（#29）

- **语义**: 患者入院前的位置。
- **来源**: `dataset/hosp/admissions.csv` 的 `admission_location` 列。
- **关联**: 与 `hadm_id` 同行。
- **保存格式**: str。缺失时写空单元格。
- **出题用途**: 题型④ 条件题干。辅助判断就诊途径（急诊 vs 转诊 vs 门诊）。

### 4.7 `discharge_location`（#30）

- **语义**: 患者出院去向。
- **来源**: `dataset/hosp/admissions.csv` 的 `discharge_location` 列。
- **关联**: 与 `hadm_id` 同行。
- **保存格式**: str。缺失时写空单元格。
- **实际值分布**（全库前 10）:

| 值 | 计数 | | 值 | 计数 |
|---|---|---|---|---|
| HOME | 194,204 | | SKILLED NURSING FACILITY | 52,657 |
| （空） | 149,818 | | REHAB | 13,845 |
| HOME HEALTH CARE | 99,305 | | DIED | 11,721 |

- **出题用途**: 题型④⑤。题型④ 中反映服务层级结论；题型⑤ 中作为离院去向背景。

### 4.8 `ed_disposition`（#31）

- **语义**: 急诊离开去向（仅急诊就诊患者有值）。
- **来源**: `dataset/mimic-iv-ed/ed/edstays.csv` 的 `disposition` 列。
- **关联**: 通过 `edstays.hadm_id` 等于当前 Visit。
- **保存格式**: str。无 ED 关联时写空单元格。
- **出题用途**: 题型④ 辅助判断急诊后去向（收治入院 vs 回家 vs 转院）。

### 4.9 DS 出院章节组（#32-#35）

以下 4 个字段均来自选定 DS 的 `text`，使用与 `chief_complaint` 相同的 DS 记录，不合并不同 DS 的章节。

#### `brief_hospital_course`（新增 #32）

- **语义**: DS 出院小结中概述的住院期间诊疗经过。
- **来源**: 选定 DS → `Brief Hospital Course` 章节。
- **章节边界**: 从标题之后开始，到下一个已知顶层标题（通常为 `Medications on Admission`）之前结束。
- **内容处理**: 去除首尾空白，保留内部原文、顺序、换行和 `___` 标记。
- **保存格式**: str。缺失时写空单元格。
- **出题用途**: 题型⑤ 条件题干信息。提供治疗经过背景，帮助判断离院指导合理性。

#### `discharge_medications`（新增 #33）

- **语义**: DS 出院小结中记录的出院带药。
- **来源**: 选定 DS → `Discharge Medications` 章节。
- **章节边界**: 从标题之后开始，到下一个已知顶层标题（通常为 `Discharge Diagnosis`）之前结束。
- **内容处理**: 去除首尾空白，保留药物名称、剂量、频次、途径、PRN 信息和列表编号。
- **保存格式**: str。缺失时写空单元格。
- **出题用途**: 题型⑤ 条件题干信息。反映需延续的药物治疗，帮助判断离院用药指导完整性。

#### `discharge_condition`（新增 #34）

- **语义**: DS 出院小结中记录的患者出院时状态。
- **来源**: 选定 DS → `Discharge Condition` 章节。
- **章节边界**: 从标题之后开始，到下一个已知顶层标题（通常为 `Discharge Instructions`）之前结束。
- **内容处理**: 去除首尾空白，保留原文。
- **保存格式**: str。缺失时写空单元格。
- **出题用途**: 题型⑤ 条件题干信息。反映离院时病情稳定程度，帮助判断随访计划紧迫性。

#### `discharge_record`（#35）

- **语义**: 出院后随访指导文本。
- **来源**: 选定 DS → `Follow-up Instructions` 章节。兼容 `Follow-up Instructions`、`Followup Instructions`、`Follow Up Instructions` 三种标题写法。
- **保存格式**: str。缺失时写空单元格。
- **出题用途**: 题型⑤ 答案来源。
- 规则延续 `rwd_benchmark_extraction_spec.md` §5.17。

### 5.3 低严重级别 / 已确认可接受

| # | 问题 | 处置 | 理由 |
|---|---|---|---|
| L1 | JSON 集合字段丢失时间维度 | 保持现状 | 出题设计以"有无"和"内容"为核心，时间维度仅用于内部排序选择 |

| L4 | 社会史（吸烟/饮酒/职业）、家族史未设独立字段 | 不设独立字段 | question_types.md 未将社会史/家族史列为独立字段类别；DS 中有 Social History / Family History 章节，如需可后续追加 |

| L6 | `pain`（疼痛评分）未纳入独立列 | 暂不纳入 | triage 表有 `pain` 列但值为自由文本（非纯数字），与 #6-#12 数值型列不匹配；如需可后续追加 |

### 5.4 order_type 数据验证发现

数据验证中发现 30 列提案中 `investigation_orders` 的 `order_type IN ('Lab', 'Imaging')` 存在实际值不匹配问题：

- `Imaging` 在 poe 表中实际不存在，影像检查的 order_type 值为 `Radiology`；
- 题型① 示例题的标准答案"十二导联心电图"对应的 order_type 为 `Cardiology`，原过滤范围会将其排除；
- Lab 医嘱的 order_subtype 实际几乎全空，具体检验项目需从 `labevents.itemid` + `d_labitems.label` 或 `poe_detail` 获取。

此问题已在 #20 `investigation_orders` 字段中修正。

## 九、通用存储规则

延续 `rwd_benchmark_extraction_spec.md` §3.4 的存储规则，补充：

- CSV 使用 UTF-8 编码，换行符 `\n`。
- `subject_id`、`hadm_id`、`primary_icd_code` 按字符串处理，保留前导零。
- 标量非必需字段缺失时写空单元格；集合字段无元素时写合法 JSON `[]` 或 `{"laboratory":[],"radiology":[]}`。
- 不使用 `nan`、`None`、`null` 字符串表示 CSV 缺失。
- JSON 对象的固定属性必须完整；源字段缺失时保存 JSON `null`。
- DS 章节字段（#15-#19, #32-#35）使用同一份选定 DS，不合并不同 DS 的章节内容。
- 生命体征独立列（#6-#12）保存数值或空单元格；源值无法解析为数值时写空单元格。
- `rhythm`（#13）保存文本或空单元格。
- `vital_source`（#14）当 #6-#13 任一非空时必须写来源标记。
