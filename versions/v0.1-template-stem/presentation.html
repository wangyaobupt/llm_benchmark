01项目定位

核心问题：LLM 在「一次就诊的不同决策节点」，能否仅依据 当时已经发生且已经可用 的信息作出合理决策？

  • 数据来源 —— MIMIC-IV v3.1 / ED 2.2 / Note 2.2 的真实住院事件流（结构化事实 + 时间关系）。
  • gold 来自真实事件 —— 答案由真实临床事件的确定性统计得出（selectivity / PSR），不由 LLM 生成。
  • 严格时间门禁 —— 所有前瞻性题目只允许使用「决策时点前已可用」的信息，后验资料与行政终点不能进题干。
  • 患者级防泄漏 —— 按患者 60/20/20 划分 development / validation / final_test，同一患者不跨集合。

本版本（v0.1）覆盖前四维：检查 / 诊断 / 治疗 / 转诊均已出题并评测；离院随访因 MIMIC 无出院后随访事件，仅完成出院文书抽取骨架，未出 MCQ、不参与本基线。

03核心方法论：出题 vs 评测的角色边界

🛠 出题 — 零 LLM

gold 答案：从真实事件流用确定性统计算出（selectivity / PSR）。
题干：固定模板 A patient presents with {主诉}…
干扰项：候选池取前 3 个非 gold 项。
纯 pandas、无随机数、无 LLM 参与生成。

🤖 评测 — 用 LLM 答题

把题目发给 OpenAI-compatible 接口，模型只回 A/B/C/D。
本版本基线模型：deepseek-v4-flash。
这是整条链路中唯一使用 LLM 的环节。

为什么 gold 不能用 LLM 生成？ 若「出题模型」与「答题模型」同源，测出的是模型家族的自我一致，而非真实临床决策能力 —— 即循环验证（circularity）。文献证据：LLM 生成的专科 gold 经医生验证「彻底错误」率达 9.15%（Gaber）；自动生成 gold 有 33.8% 的正确答案被医生改掉（EHRNoteQA）。因此 gold 只来自真实事件 + 人工临床审核。

04gold 语义：不同维度用不同统计量

selectivity（特异性 / lift）

selectivity = P(候选 | 主诉) / P(候选)
衡量「该主诉把这个动作的概率抬升了几倍」。
适用：检查 / 治疗 / 转诊 —— 先验高的普适动作，需要区分「判别性」与「普适」。

PSR（概率×特异性×可靠性）

PSR = share × selectivity × reliability
兼顾「常见 + 判别 + 可靠」三者。
适用：诊断 —— 单病种先验极低，纯 lift 会把极稀有疾病顶到最前而剧烈波动。

05b数据层 · 契约与清洗（依据代码）

契约：一条事件 = 41 个 required 字段

  • 时间四元组：event_time / source_available_time / available_time / recorded_time，显式区分「发生 / 源可见 / 有效可见 / 记录」。
  • 后验标记：evidence_phase ∈ source_event / post_hoc / administrative_end，决定能否进前瞻题干。
  • 溯源：raw_row_ref（分片#行号/表[下标]）回连原始 JSONL 源行。
  • 质量：quality_flags（28 枚举）+ event_kind（27 枚举）。

清洗：封闭目录 + transformer 一进多出

  • 33 表封闭目录：21 事实源 / 6 support / 6 context，逐表登记 SourceSpec。
  • 统一签名：(SourceRow, AdmissionContext) → list[dict]，共 26 个 transform_*。
  • 身份策略：native_key → composite_key → 行哈希+序号，不删原始重复行。
时间语义每表一条 TimePolicy：检验/eMAR「可见 = max(发生, 存库)」；POE「缺订单时间即拒绝」；出院 ICD「无时间、标 post_hoc」；ICU 区间「完成前不可见」。绝不静默填默认值，缺失一律 null + flag。

05c数据层 · 标准化、编排与审计

标准化：冻结映射 + 一致性门禁

  • 零 LLM：terminology.py 版本锁定（event-terminology/1.1.0）+ 人工审核同义词 + 单位别名表。
  • 判定链：source-code（NDC 11 位 / GSN 6 位）→ 文本映射 → 否则 unresolved，不猜测。
  • 一致性门禁：映射表与事件应用不一致即抛 MAPPING_APPLICATION_MISMATCH。

编排：固定 8 步 + 复跑 + 原子发布

  • clean → 验收 → normalize → 验收 → 换 batch size 复跑（5000 vs 777）→ 比对 SHA-256。
  • 全过才 os.replace 原子发布；任一步失败不留正式目录。
  • 独立审计：normalization 审计验证「除 8 个归一化字段外事实不变」。
审阅层只读 + 追加式：人工决定写 annotations.jsonl，不改 Parquet；确定性纠正回规则层改代码重跑。三铁律贯穿全程 —— 可追溯 / 不伪造 / 门禁 fail-closed。

09关键发现

  • ① 诊断「少而精」最成功 —— 主诊断 + PSR + 归一化后仅 24 条验证通过，DeepSeek 达 95.83%（高共识教科书题）。
  • ② 治疗 T2/T3 相对高 —— 执行 87.50%、手术 73.08%，「做了什么」比「该开什么」更易判。
  • ③ 检查 laboratory / clinical_order 与转诊是短板 —— 48.28% / 19.05% / 60.61%，laboratory 需补唯一性过滤 + panel 粒度审核。
  • ④ 离院 F1 信号稀疏 —— 出院全文可得（92%），但显式「随访时间窗」仅 ~5%，完整 F1 需文本 NER/RE 支路。
  • ⑤ 题干信息量是难度旋钮 —— 当前题干仅含归一化主诉，信息量极低；分数 = 决策时点信息量 × gold 轨道选择。

10局限与下一步

⚠ 当前局限

  • 产物均为 exploratory_unreviewed，gold 语义 / 阈值 / 词表为占位值，未冻结。
  • 单模型基线（仅 deepseek-v4-flash），无跨模型对比、无置信区间。
  • 题量小：诊断 24、转诊 33，统计功效有限。
  • 干扰项 naive：固定池取前 3，非层次化「同层混淆项」。

➡ 下一步

  • 关闭上游人工门禁（归一化 100 条试审 + 文本 NER 双标裁决）。
  • 冻结协议 → 扩容题量 → 层次化干扰项。
  • 多模型评测（配 Wilson CI + 配对检验）。
  • 基于病例具体特征的题干升级（grounded）。
定位：本快照是「模板题干 + 确定性 gold」的 基线版，用于回答「这套 bench 大致能拉开多少差距、哪几维最灵敏」，而非正式榜单。
